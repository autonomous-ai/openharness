# Harness Pro firmware: Pod port inventory

SRC = `/private/tmp/claude-503/x/podwt/devices/harness-device/firmware` (read-only). Paths below are relative to `SRC/main`.
`UH` = `ui/habitat/ui_habitat.c`. Line numbers are from the SRC snapshot this inventory was made from.

Build facts: `DEVICE_POD` requires `DEVICE_PRO_COMPANION` (CMakeLists.txt:267-273), so every Pod build is also a
Pro-companion build. `DEVICE_POD` code sits on top of Pro code that Pod never shows. `pod_ui_*` (pod_glue.c/.h) is reused
unchanged and already holds the 4 s / 0.8 s / 5 s focus timers, the sweep walk, the notice, the scroll sink, the
clock edge, and pane navigation. `pro_app.c` only has to feed it correctly and perform its `pod_out_t` effects.

Destination key: `pro_app_*` = callbacks in `app/pro_app.c`; `pro_cable` = `cable/pro_cable.c`; `pro_frame` = `display/pro_frame.c`
(from display_habitat.c); `pro_touch` = `display/pro_touch.c` (from touch_habitat.c); `pro_voice` = `audio/pro_voice.c`
(from audio_client_habitat.c). "perform" = what `pod_perform()` does with a `pod_out_t`.

## 6. Open points for the owner

1. **Stale busy vs the Pod model.** `ui_prune_stale_busy` (25 s) only clears Player-1 flags. The Pod model stays WORKING without `done`/`error`/link drop. Keep this or add a prune that feeds `pod_ui_turn(.., "done")`?
2. **Session change.** Under PRO, `event()` resets busy/player when the `session` differs (UH:5792-5803). Pod got no turn event from it, and the new project does not carry `session`. Skipped unless wanted.
3. **`voice.error`.** SRC shows nothing for Pod (the MESSAGE view is hidden). Proposed: `pod_ui_notice(message)`.
4. **Pane memory size.** SRC holds 128 entries, Pod holds 32 agents. Library rows can send events for agents beyond 32.
5. **`player.context`, `speech`, `product`/`hw` in hello, `wifi.configure`.** Not in the plan's hello list; confirm which are kept.
6. **`pod_ui_status`** exists in `pod_glue.c` but ui_habitat.c never calls it (status comes from the library rows and turn events).

## 7. Owner decisions (2026-10-11)

The owner approved every point in section 6, as follows:

1. **Stale busy.** Keep today's behaviour: an agent stays WORKING until `done`, `error` or the link drops. There is no 25 s expiry.
2. **Voice errors.** `voice.error` shows as a Pod notice (`pod_ui_notice`).
3. **Voice gate.** `pro_voice_block_reason` reads `pro_app`'s set of open questions instead of `s.notice[]`.
4. **Unused feeds.** `pro_app_context` is a no-op for now. `pod_ui_status` gets no new caller.
5. **Unknown agents.** Events for an agent Pod does not hold (beyond its 32) are ignored.
6. **Session change.** The session-change reset is not ported.
7. **Hello fields.** The hello keeps `product` and `hw` and drops `speech`. The full key list is: `proto`, `board:"pro"`, `product`, `hw`, `swarms:"members-v1"`, `recap:"long-v1"`, `activity:"steps-v1"`, `player:"library-v1"`.
8. **Focus timers.** `pro_app` calls `pod_ui_focus` only. The 4 s, 0.8 s and 5 s focus timers stay in `pod_glue.c`.
