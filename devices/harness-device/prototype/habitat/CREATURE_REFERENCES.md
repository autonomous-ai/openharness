The [original ten-creature gallery](CREATURE_GALLERY.md) is the first comparison set. [Study 02 / gallery .4](CREATURE_GALLERY_02.md) now installs ten more reference/adaptation studies. ## Directions to compare

These are working categories for this experiment, not a definitive art-history taxonomy.

| Direction | Appearance | Reference | What to explore |
|---|---|---|---|
| **Tiny ASCII companions** | A few lines of punctuation, with a readable face | User's cat | Gaze, slow blinks, a small head tilt, expressive pauses |
| **Hand-drawn line characters** | Deliberate outlines, recognizable anatomy and poses | Original ten; Joan Stark; Face Study; Stone Story | Turning, stretching, grooming, curling up, anticipation and recovery |
| **Shaded ASCII creatures** | Dense letters and punctuation create volume | Terminal Party Parrot; user's converter animation | Strong silhouettes, coordinated body motion, quiet versus energetic loops |
| **Solid-block / filled-glyph text art** | Filled shapes using `█ ▄ ▀ ▓ ▒ ░`, dots and related glyphs | Terminal sprites, Nyan Cat, Brrtfetch octopus, ANSI art traditions | Monochrome silhouettes and restrained color; eyes and limbs cut into a substantial body |
| **PETSCII / custom textmode** | A graphic character set supplies blocks, diagonals, curves and patterns | Polyducks | Sculptural forms and characterful poses assembled from a small glyph vocabulary |

Image/GIF conversion is an **authoring method**, which can produce several of these styles. It is recorded separately below.

## Set C — solid blocks and graphic characters

Solid blocks such as `█`, half blocks `▀ ▄`, and shading `░ ▒ ▓` are **text glyphs outside 7-bit ASCII**. The [Unicode Block Elements chart](https://www.unicode.org/charts/PDF/U2580.pdf) identifies these characters. Historical ANSI art often combines a PC graphic character set with color controls; PETSCII has its own character repertoire. A PNG or GIF preview of textmode work is not itself the character source.

|---|---|---|

## Set D — user-supplied conversion and animation references

### Brrtfetch octopus — explicitly liked

[User's Reddit post](https://www.reddit.com/r/unixporn/comments/1nz31gv/oc_brrtfetch_animated_ascii_art_for_your_fetcher/) · [Brrtfetch source, ferrebarrat](https://github.com/ferrebarrat/brrtfetch) · [octopus source GIF](https://github.com/ferrebarrat/brrtfetch/blob/main/gifs/defaults/brrt.gif) · [terminal demonstration](https://github.com/ferrebarrat/brrtfetch/blob/main/docs/readme-md-main.gif)

The user specifically praised both the octopus and its movement. Preserve this exact example as a leading reference for the next animation comparison. Brrtfetch converts a source GIF into colored character frames; its author says the octopus source was made through an image-generation and animation workflow. The README's example uses an 80-column rendering at 17 fps. Those are desktop demonstration settings, not a measured target for our device. [Project documentation](https://github.com/ferrebarrat/brrtfetch).

Inspected the source animation and the terminal demo as sequences of frames. The large round head, stable eyes and mouth, and curling/uncurling tentacles keep the identity clear while the body moves. The source GIF has 125 frames; its encoded durations total 5.21 seconds. These source timings differ from Brrtfetch's configurable playback cadence.

The inspected renderer at commit `d32d15331089e31591520013fe121d44f29ca31d` maps brightness to a mixture of spaces, punctuation and Unicode circles: `◌ ● ⦾ ⦿ ⬤`. At the demo's high multiplier, its filled-circle choice dominates. Classify this as **filled-glyph textmode**, despite the project's broad use of the name ASCII. [Actual mapping](https://github.com/ferrebarrat/brrtfetch/blob/d32d15331089e31591520013fe121d44f29ca31d/go/main.go#L284).

For Harness, explore preparing the character frames on the computer and storing them in firmware. Compare monochrome and restrained-color versions at the actual round-screen size. Preserve the original motion timing when evaluating the movement. This authoring proposal adds no app wiring.

### Image to ASCII — Design Minis / nanmu

[User's Design Minis link](https://www.designminis.com/tools/image-to-ascii) points to [imagetoascii.art](https://imagetoascii.art/). The tool exposes width, character selection, tonal controls and dithering. Its page distinguishes ASCII-only styles from **Blocks (`█▓▒░ `)** and offers text/ANSI export alongside image exports. Its GIF input currently uses a single browser-provided frame, so do not assume it exports an animation.

Use it to compare the same source in several text styles and densities. Export actual characters for firmware; use image previews for reference review. The site's large 180–220-column showcase examples need a separate small-screen study before adoption. These findings come from inspecting the page and its published page source; no user files were uploaded. [Tool](https://imagetoascii.art/).

### Animated image/GIF conversion — r/vibecoding

[User's post](https://www.reddit.com/r/vibecoding/comments/1uhr11l/ascii_art_always_fascinated_me_so_i_build_a/) · [animated text-art example](https://i.redd.it/fa78mivr8z9h1.gif) · [source animation credited by the poster](https://tenor.com/view/chango-lero-lero-leronlero-gif-4368030733658011142)

The inspected example has eight GIF frames: a shaded figure changes its arm and head poses while retaining its outline. It is a useful example of recognizable whole-body motion carried through a text conversion. The poster says their converter is not yet released and links [ASCII Art EU](https://www.asciiart.eu/image-to-ascii) and [Asciify](https://asciify.org/editor) as other tools; those are not the poster's own converter.

## Next comparison and rendering approach

Retain the first ten as the baseline. Add examples spanning tiny line art, detailed hand-drawn movement, shaded animation and filled block silhouettes. Compare silhouette recognition, facial readability, natural pauses, animation coherence and how distracting the loop feels on a desk. Do not equate more characters or a higher frame rate with a better companion.

The [supplied daemon craft notes](DAEMON_CRAFT_NOTES.md) add several useful principles: keep identity stable across poses; use eyes and posture deliberately; author poses with holds; tie a walking cycle to distance; make color supplementary; give quiet holds as much attention as movement. Their eight-cell status-line limits, two-cell changes and event-only animation policy belong to that application surface. The device's local visual experiment should also test the richer octopus-style loop the user likes. Growth, lore and agent-event behavior are recorded context, not new implementation scope.

For converted animation, crop the source and simplify its background before conversion, use a consistent character ramp/palette across frames, preserve frame holds, then inspect for flicker and hand-clean important features. Convert before the firmware build. The device should receive prepared text frames and timing data.

The first gallery's **25 × 9** grid was an initial art choice, not the display's inherent limit. Study 02 tests several cell sizes and adds compact Unicode Block Elements atlases alongside ASCII 32–126. It uses the same C compositor; arbitrary PETSCII alphabets and per-cell ANSI colors are not supported by this addition. Color-rich references are shown as monochrome text conversions. See [font data](../../firmware/main/ui/habitat/creature_font.c) and [compositor structures](../../firmware/main/ui/habitat/terminal.h).

Measure CPU time, bytes transferred, memory and touch responsiveness once a candidate is implemented. No new device speed or memory claim is established by this research. Third-party previews remain linked with credits; commercial adoption needs the artwork's own applicable terms, independently of a converter's code license.
