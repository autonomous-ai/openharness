# The dial lists, follows, talks to and opens agents in Rex (2026-11-25)

[Rex](https://www.superlogical.com/rex/docs) is a terminal multiplexer with a macOS app. Its sessions hold windows (the
app's tabs), and its windows hold blocks (panes). This spec adds Rex as one more host app of the dial. It uses the
screens the dial has today, and it adds none: the APPS picker, the agent's face, the panes list, a tap, a rest and
words. The pattern is Orca's (`cli/src/cable/hosts/orca.ts`) and Zellij's (`cli/src/cable/hosts/zellij.ts`).

## What `main` does today (70e8c496d6, measured on a real dial on 2026-11-25)

The test used a real dial (fw 0.1.1-dev.6dcb285e7d), Rex 0.1.0 (2061) with server API revision 8, Claude Code 2.1.332
and Codex 0.166.0.

| Case | What happened |
|---|---|
| A dial plugged in | The devices process set up Claude Code's plugin, Codex's skill and the VS Code and Cursor extension. Nothing was clicked |
| A Claude Code turn in a Rex pane | The dial got `turn.started`, `turn.done` and `summary`, and beeped |
| Claude Code asks (AskUserQuestion) in a Rex pane | The dial showed the agent waiting |
| Words said at the dial to that Claude Code | They reached the session through the plugin's mod (`[device] voice · mod`), Vietnamese included. While its question was open they were held as its next prompt, as designed |
| A Claude Code started before the plugin was installed | It has no mod. A tap on its face said "See it in Rex": no route takes its words |
| The page a Rex agent is on | "Other". Its hint `TERM_PROGRAM=rex` is not in `PROGRAM_APPS`, and Rex sets no `__CFBundleIdentifier` (`hostDetect.ts` `detectApp`) |
| A tap on a Rex agent | Rex does not switch to its pane: there is no Rex adapter |
| Codex in a Rex pane | Its words have no route: it has no mod, and its session is not in Harness's Codex home |
| Following focus in Rex | None |

## Goal

With Rex on this computer and a dial attached:

1. A Rex agent is on the "Rex" page of APPS, and its face reads "Rex".
2. A tap, or a rest on its face, switches Rex to its window and block. A tap also brings Rex to the front.
3. The dial's words reach any Rex agent at its prompt, a Codex one and a Claude Code with no mod included. A Claude Code
   with a mod keeps its mod's route first (`observed.ts` `send`).
4. Clicking a block or a tab in Rex turns the dial to that agent, as Orca's focus does.
5. The ring is in Rex's order (window, then block), and a window the person renamed names its agent.

The person does nothing for any of it: no setting, no Rex config change and no `harness device` command.

## Design

Everything is in the devices process, as for every host (cli/AGENTS.md rule 7). The core never hears of Rex.

### 1. The hook names the session (`cli/hook/notify.mjs`)

- Add `REX_SESSION` and `REX_SERVER` to `HOST_HINTS`, and both to `WHOLE_HINTS`: a cut one would name another session
  or server.
- An older daemon ignores the two new hints. An older hook sends only `REX_BLOCK`, so its agent has no pane (below) and
  keeps today's behavior.

### 2. Rex is an app (`cli/src/cable/hosts/hostDetect.ts`, `scannedApp.ts`)

- `PROGRAM_APPS`: `rex: 'rex'`. `APP_BUNDLES`: `rex: 'com.superlogical.rex'`. `open.ts` then brings Rex forward with
  that bundle id, and `frontApp.ts` knows Rex in front, because both read `BUNDLE_APPS`. `NAMES` already has
  `rex: 'Rex'`.
- `PTY_HOSTS`: `rex: 'rex'`, matched only when the maker's path ends in `Rex Server.app/Contents/MacOS/rex`. A bare
  basename `rex` is too common a name to trust.
- `types.ts` already says Rex "stays on its app's" page, and it is not a `Nest`. Rex is the app here, so its page is
  "Rex". A tmux inside a Rex pane still gets tmux's page, as now.

### 3. Finding `rex` (`cli/src/cable/hosts/rex.ts`, `rexFinder`)

- Use `rex` on this process's `PATH`. Otherwise use the fixed path above, under the daemon's own `HOME`. The file must be
  a regular, executable file owned by this user. Otherwise the result is "absent", asked again at the next attach, as
  `zellijFinder` does.
- Every command runs with no shell, with the text as one argument and `RUN_TIMEOUT_MS` (10 s), through `OrcaDeps.run`.
- Only the default local server is reached. A hint whose `REX_SERVER` is not
  `unix://<HOME>/Library/Application%20Support/rex/server.sock` gives no pane: a shared, remote or login server is a
  follow-up. The daemon never reads another process's environment.

### 4. The Rex adapter (`HostAdapter`, `cli/src/cable/hosts/rex.ts`)

- **`paneOf(place)`:** `REX_SESSION` matches `^session:[0-9a-f-]{36}$`, and `REX_BLOCK` matches `^block:[0-9a-f-]{36}$`.
  The server must be the default one.
  - The PTY maker must be Rex Server (section 2). Then the pane is the agent's own.
  - Otherwise, for example a multiplexer inside the Rex pane, it is `held:`. A held pane takes a tap only and no words,
    as Orca's `HELD` and Zellij's.
- **`canFocus`:** `rex` was found.
- **`focus(pane)`, a tap:**
  1. `rex block focus -s <session> <block>`.
  2. When the app's client does not show that session, `client.perform session.select` to each local `kind: app`
     client (`rex client ls --json`).
  3. `open.ts` brings Rex forward.

  With Remote Control off, step 2 is refused. The tab and block still change, and Rex comes forward on the session it
  shows. The log gets one fixed line (`[device] open · rex · session not shown`), counted.
- **`canShow` / `show(pane)`, a rest:** step 1 only, and only while Rex is the settled front app. A rest never changes
  which session the app shows.
- **`canType` / `type(pane, text, engine, atPrompt)`:** only an own pane. Words go only through the existing `send`
  checks: needs-you refuses, working refuses, and the mod and Codex queue come first (`observed.ts`).
  1. Read `rex block call -s <session> -b <block> process`. Its `foreground.pid` must be the agent's pid, the hook's
     `callerPid`. Otherwise the result is `failed`: the block holds a shell or another program now.
  2. `rex send -s <session> -b <block> <text>`. Control characters become spaces (`CONTROL`), and the text is at most
     `MAX_TEXT`.
  3. Wait the settle every typed host waits: `INJECT_PASTE_DELAY_BASE_MS` plus 1 ms per 60 characters, at most
     `INJECT_PASTE_DELAY_MAX_MS` (`lib/submitTiming.ts`, as `vscodeTerminals.ts`). This is the Codex Enter loss in the
     spike.
  4. Ask `atPrompt()` again and read `process` again, then `rex send-key -s <session> -b <block> enter`. If either check
     fails, nothing more is typed, and the result is `failed`.
- **`voiceRefusal`:** none. With no route, the dial's own "See it in Rex" stays.

### 5. Follow focus, order and names (`cli/src/cable/hosts/rexSource.ts`), as Orca's (2026-11-16 design)

- **When:** a dial is attached, Rex is the settled front app, and `rex` was found.
  - Run one `rex events -s <session> --json` per session that holds an agent on Rex's ring. That is at most 16, because
    the ring holds 16.
  - A stream is stopped when its session has no ring agent left, when Rex leaves the front, and when the dial detaches.
  - A stream that ends starts again only at Rex's next settle. There is no retry loop.
- **Reading:** on `active_window_changed`, `session_view_changed` or `window_label_changed`, one
  `rex window ls -s <session> --json` runs.
  - Reads of one session run one at a time. A change during a read asks for one more read after it.
  - An answer over 1 MiB, or bad JSON, is dropped with a fixed reason.
- **Focus:** the active window's `focused_block_id` names an agent's own pane, and the dial turns to that agent, as a
  tab report does (#4331).
  - Each block the dial itself switched to is kept for 2 s, at most 8 of them. A focus within that time is the dial's
    own echo and is skipped (Orca's decision 5).
  - While a stream runs, a prompt in a Rex agent no longer moves the dial. Prompt follow stays for a Rex with no stream.
- **Order:** Rex's ring goes in window order, then in block order. Block order is the layout tree, `before` before
  `after`. A Rex agent in no window read goes after them, in ring order. The order is read again when the ring's agents
  change, as Orca's (decision 2).
- **Names:** a window whose label is not `Window <8 hex>` names its agents, above the session's own name (Orca's
  decision 8).
- **Not followed:** the person picking another session in Rex's sidebar emits no event (spike). The dial turns at their
  next click or tab change in that session.

## Design (docs/feature-design-rules.md)

Reviewed revision: ______  Reviewer: ______

1. **Growth:** nothing is stored on disk. In memory there are the stream per session (stopped at detach, when Rex leaves
   the front, or when the session has no ring agent), the last `window ls` per session (dropped with its stream), and
   the echo guard (8 entries, 2 s). [x]
2. **Concurrency:** one `window ls` at a time per session, and one stream per session. `type` re-reads `process` and
   `atPrompt` right before its Enter. The adapter types into one block at a time: a second word to the same block while
   one types is `failed`, as `vscodeTerminals.ts` keeps its `sending` set. [x]
3. **Read cost:** one `window ls` per Rex change. That is a few KB for a few windows, and answers over 1 MiB are
   dropped. No poll: nothing is read between changes. A test pins the 1 MiB bound. [x]
4. **Scale:** at most 16 streams (`RING_PLACES`), each one `rex` process that idles in a read. At 10x (160 sessions)
   only the 16 that hold ring agents are streamed. The metric that warns first is `rex` spawns per minute, counted in
   the day's tally. [x]
5. **Compatibility:**
   - An older hook sends no `REX_SESSION`: no pane, as today.
   - An older daemon ignores the new hints.
   - Firmware is unchanged: `apps`, `caps` and `host` exist.
   - Every Rex command used was run on API revision 8.
   - The docs already show flags this Rex CLI lacks (`rex run --interactive`), so only spike-verified commands are
     used.
   - Readers of `PROGRAM_APPS`, `APP_BUNDLES` and `PTY_HOSTS` come from a search of the code: `detectApp`,
     `BUNDLE_APPS` (`open.ts`, `frontApp.ts`) and `ptyHostOf`. [x]
6. **Migration and rollback:** none: no stored field. A rollback to the previous CLI puts Rex agents back on "Other",
   with no other effect. [x]
7. **Audience:** local only. The commands go to the person's own Rex socket, through a binary owned by this user.
   Nothing leaves the computer, and no text is logged, only fixed reasons and counts. [x]
8. **Identity:** the devices process runs as the person, the same uid as their Rex server. No login is used. N/A
   beyond that. [x]
9. **Failure:**
   - `rex` absent or failing: the agent keeps today's caps, the dial says "See it in Rex", and the log has one fixed
     line.
   - A typed word refused by the checks: the dial says "<name> did not answer." (`observed.ts`).
   - Remote Control off: the tap changes the tab and block, and Rex comes forward on the session it shows, with one
     counted line.
   - A stream that ends: follow stops until Rex's next settle. [x]
10. **Platforms:**
    - macOS: the Rex app.
    - Linux and Windows: Rex runs servers there but has no app on this computer to bring forward. Their panes keep
      `TERM_PROGRAM=rex` and get the "Rex" page, with no adapter (follow-up).
    - iOS: N/A. [x]

## Tests

- **Unit, with recorded output** (`cli/src/testing/recordedRex.ts`, from the spike):
  - `paneOf` forms;
  - held vs own;
  - `type` refuses when the foreground pid differs, and when `atPrompt` turns false before Enter;
  - the settle is waited;
  - `window ls` gives the order, the focus and the renamed label;
  - the echo guard;
  - stream start and stop rules.
- **Hook test:** `REX_SESSION` and `REX_SERVER` are sent whole.
- **End to end** (`cli/e2e/dialHostRex.e2e.ts`): on the real daemon with a fake dial, like `dialHostZellij.e2e.ts`. It
  uses the suite's hooked fake Claude Code and Codex in a Rex session of the test's own. It is skipped where `rex` is
  absent.
  - Open point: whether the test can run a private Rex server instead of the person's.
- **On a real dial before merge:** the six "After" rows above, with Claude Code and Codex.
