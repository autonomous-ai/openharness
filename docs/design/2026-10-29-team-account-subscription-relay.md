# How a Harness Team account spends its owner's subscriptions

On a Mac with a Harness Team account, the owner's Harness daemon can let Claude Code and Codex running as the separate Team account use the owner's subscriptions. The Team account receives a revocable relay token; the owner's provider sign-ins stay in the owner's daemon and stores. This describes the implementation on `origin/main` at `1b091c3e5` (after `fb4203ced`).

## The owner's relay

`cli/src/superTabs/service.ts` (`createSuperTabsService`, `port.connected`) starts a `realTeamRelayPublisher` when the owner's daemon connects. `cli/src/team/relay.ts` (`TeamRelayPublisher.start`, `pass`) checks immediately and then once a minute. It publishes only when the root-owned Team configuration exists and names this daemon's OS user as the Mac owner. The Team daemon never publishes a relay. If the configuration no longer names this owner, `TeamRelayPublisher.close` withdraws the handoff and closes the relay; stopping the service does the same.

The publisher starts `startSubscriptionRelay` from `cli/src/lib/subscriptionRelay.ts`. It binds an ephemeral port on `127.0.0.1`, so the HTTP server listens only on this Mac. It accepts `/claude/*` and `/codex/*` requests carrying the guest token as a bearer token or `x-api-key`. Unknown provider paths return 404, invalid tokens 401, and request bodies over 32 MiB 413. For an accepted request, `handle` reads the owner's credential, sends the request to the corresponding provider with the owner's authorization, and streams the response back. A provider 401 causes one refresh and retry. Errors returned to the client do not include vendor response bodies or tokens. The relay keeps token digests in memory and can revoke every token for a guest; closing it closes the listener and drops that in-memory map. (`cli/src/superTabs/service.ts`, `createSuperTabsService`; `cli/src/lib/subscriptionRelay.ts`, `startSubscriptionRelay`, `handle`, `presentedToken`, `upstreamHeaders`.)

## Handoff file and access

On macOS the path is `/Users/Shared/.harness-team-relay-<owner>/relay.json`, where `<owner>` is the owner's local account name. `cli/src/team/layout.ts` (`teamLayout`) supplies the directory, and `cli/src/team/relay.ts` (`teamRelayFile`) appends `relay.json`. Its JSON has exactly the relay URL and the Team account's token, for example:

```json
{"url":"http://127.0.0.1:<port>","token":"<revocable-relay-token>"}
```

`publishTeamRelay` creates the owner-specific directory with mode `0700`, verifies it belongs to the owner, and sets a macOS ACL giving the Team account list, search, and read-attributes rights on that directory. It writes a temporary file with mode `0600`, grants the Team account read and read-attributes rights on it, then renames it atomically to `relay.json`. For ordinary user access, the owner reads through owner permissions and the named Team account through its ACL; other local users are not granted access (a system administrator/root can override file permissions). `readTeamRelay` checks that the directory and file are regular owner-owned objects, rejects unsafe permissions and symbolic links, and accepts only a loopback URL and a token of the expected shape. (`cli/src/team/relay.ts`, `publishTeamRelay`, `allow`, `teamRelayFile`, `readTeamRelay`; `cli/src/team/layout.ts`, `teamLayout`.)

The relay token is minted once for the Team account and retained by the owner daemon while the grant is published. It is revocable and is not an owner sign-in. On Linux the corresponding handoff lives under `/var/lib/harness` with `setfacl`; Windows uses the Team relay directory under `C:\ProgramData\Harness` and a Windows ACL. (`cli/src/team/relay.ts`, `TeamRelayPublisher.pass`, `setfaclGrant`, `publishWindowsTeamRelay`, `withdrawTeamRelay`.)

## Engine launches in the Team account

`cli/src/team/relay.ts` (`teamRelayLaunch`) only supplies the relay to a Harness Team daemon for Claude Code or Codex, and only when that engine is not signed in in the Team account. An engine's own Team-account sign-in takes precedence. The Team daemon reads the grant from `relay.json` at launch (`readTeamRelay`). `cli/src/core/agents/create.ts` (`createAgentCreator`) and `cli/src/lib/launchOverrides.ts` (`prepareLaunchOverrides`) call the relay launch hook for agent creation and relaunches.

- **Claude Code:** `claudeRelayEnv` in `cli/src/lib/subscriptionRelay.ts` sets `ANTHROPIC_BASE_URL` to the relay's `/claude` route and `ANTHROPIC_AUTH_TOKEN` to the Team account's relay token. `teamRelayLaunch` also records Claude Code's first-run onboarding as complete in the Team account's home so nobody must answer its first-run screen. (`cli/src/team/relay.ts`, `teamRelayLaunch`, `realTeamRelayLaunch`; `cli/src/lib/subscriptionRelay.ts`, `claudeRelayEnv`.)
- **Codex:** `codexRelayArgs` selects the `harness_owner` custom API-key provider, sets its base URL to `/codex`, uses the `HARNESS_RELAY_TOKEN` environment variable as `env_key`, and selects the Responses API. `codexRelayEnv` supplies that variable. Before each Codex launch, `teamRelayLaunch` calls `prepareCodexHome`. That function asks the relay for `/codex/models?client_version=<version>` using `installedCodexVersion` (or the documented in-code fallback), then atomically writes a successful nonempty model list to `models_cache.json` in the Team account's Codex home. If the fetched list does not offer a top-level model saved in `config.toml`, `dropUnofferedModel` removes that saved model so Codex can start with a model the owner is offered. A failed or empty model-list fetch leaves the previous list in place. (`cli/src/lib/subscriptionRelay.ts`, `codexRelayArgs`, `codexRelayEnv`; `cli/src/team/relay.ts`, `teamRelayLaunch`, `prepareCodexHome`, `installedCodexVersion`, `dropUnofferedModel`.)

The Team account does not receive the owner's Claude credentials, Codex `auth.json`, OAuth access or refresh tokens, or Keychain contents. The handoff contains only a loopback URL and relay token. Claude Code receives the relay token in its environment; Codex receives it there as an API key. `prepareCodexHome` removes a prior relay-shaped Codex sign-in, while preserving a Team account's own sign-in. (`cli/src/team/relay.ts`, `publishTeamRelay`, `readTeamRelay`, `teamRelayLaunch`, `prepareCodexHome`; `cli/src/lib/subscriptionRelay.ts`, `claudeRelayEnv`, `codexRelayEnv`, `isCodexRelayAuth`.)

## Owner sign-in and refresh

`createOwnerSubscriptions` in `cli/src/lib/ownerSubscriptions.ts` reads the owner's Claude Code sign-in through `readClaudeStored`: on macOS it tries the `Claude Code-credentials` login Keychain item, then `~/.claude/.credentials.json`. It reads Codex from `~/.codex/auth.json`. `read` extracts the provider access token and, for Codex, its account id. These reads happen in the owner's daemon, not the Team account. (`cli/src/lib/ownerSubscriptions.ts`, `createOwnerSubscriptions`, `read`, `readClaude`; `cli/src/lib/agentCredentials.ts`, `readClaudeStored`, `readClaudeKeychain`, `claudeCredentialsPath`, `codexAuthPath`.)

`startSubscriptionRelay` calls `expired` before sending a provider request; tokens expiring within 60 seconds are refreshed first. If a provider returns 401, it calls `refresh` and retries once when a different access token is returned. `refreshNow` uses an in-process single-flight promise per provider and a cross-process lock file under the owner's Harness data directory. After acquiring the lock it re-reads the owner's sign-in: if another process has already replaced the stale access token with a still-valid one, that credential is used without another refresh. Otherwise it posts the refresh token to the configured provider endpoint. (`cli/src/lib/subscriptionRelay.ts`, `handle`; `cli/src/lib/ownerSubscriptions.ts`, `expired`, `createOwnerSubscriptions`, `refreshNow`, `postToken`.)

For Claude Code, a refreshed credential is written back to the same source: the existing Keychain item, or `~/.claude/.credentials.json`. The Keychain writer sends the secret through `security -i` on stdin; file writes use an atomic rename and preserve the existing mode (or use `0600`). Codex refreshes write the rotated token fields and `last_refresh` back to `~/.codex/auth.json` with the same atomic, mode-preserving file write. Thus a relay refresh updates the owner's sign-in store. (`cli/src/lib/ownerSubscriptions.ts`, `refreshClaude`, `refreshCodex`, `writeKeepingMode`, `securityKeychain`.)

```text
Harness Team account                   Owner's daemon                    Providers
--------------------                   -------------                      ---------
Claude Code -- /claude + relay token -> relay -- owner OAuth bearer -----> Anthropic API
Codex ------ /codex + relay token ---> relay -- owner OAuth bearer/account -> ChatGPT Codex
    |                                      |
    | /codex/models before launch          | reads, refreshes, writes back
    v                                      v
Team Codex home                       Owner sign-in store
models_cache.json                     Claude Code Keychain/file;
config.toml                           Codex ~/.codex/auth.json

                     relay.json in /Users/Shared
                     URL + revocable relay token
                     readable by <owner> and <team-account>
```

## History

Commit `7a043fa40` (CLI 0.5.1) signed Codex into ChatGPT through the relay. `codex exec` accepted that sign-in, but Codex's interactive screen refused it during startup. Commit `aab3905db` (CLI 0.5.2) returned to the API-key provider and fetched the owner's model list into `models_cache.json` before launch. Commit `462d44ae5` (CLI 0.5.6) also removes a saved model the owner is not offered; a saved `gpt-5.5` had left Codex waiting on a model-choice screen. The current mechanisms are in `cli/src/lib/subscriptionRelay.ts` (`codexRelayArgs`, `codexRelayEnv`, `isCodexRelayAuth`) and `cli/src/team/relay.ts` (`prepareCodexHome`, `dropUnofferedModel`).

## Design

1. **Growth:** the published handoff is one file per owner and is withdrawn when the publisher closes. The relay token map lives only for the relay process; closing it drops the map. Codex's model cache is replaced on a successful fetch and otherwise retained. There is no persistent relay history. (`cli/src/team/relay.ts`, `TeamRelayPublisher.close`, `withdrawTeamRelay`, `prepareCodexHome`; `cli/src/lib/subscriptionRelay.ts`, `startSubscriptionRelay`.)
2. **Concurrency:** `TeamRelayPublisher.tick` coalesces passes in one owner daemon; relay refreshes are single-flight per provider in one process and use a provider-specific lock file across participating processes. Publishing uses a temporary file and rename. Owner CLI refreshes do not use a lock shown in this code, so simultaneous writes by the owner's CLI and relay are not fully serialized here. (`cli/src/team/relay.ts`, `TeamRelayPublisher.tick`, `publishTeamRelay`; `cli/src/lib/ownerSubscriptions.ts`, `refreshNow`, `acquireLock`, `writeKeepingMode`.)
3. **Read cost:** each provider request reads the relevant owner credential and forwards one request; each Codex launch requests the model list and reads/writes only the Team account's Codex home files involved in preparation. The source sets a 32 MiB request-body limit, but gives no bound for model-list size or request rate. (`cli/src/lib/subscriptionRelay.ts`, `handle`, `readBody`; `cli/src/team/relay.ts`, `prepareCodexHome`.)
4. **Scale:** at 10x concurrent relay use, the code has no stated capacity target or load metric. Per-request logs include provider, method, path, status, and a short guest fingerprint; they do not record latency or throughput. Relay errors and provider status are the first signals available in this implementation. (`cli/src/lib/subscriptionRelay.ts`, `handle`, `fingerprint`.)
5. **Compatibility:** the handoff JSON has no version field. Codex's model-list request includes its installed client version, with a fallback when it cannot be read. The owner daemon attempts Team-account refresh after publisher passes, but this code does not define protocol negotiation between old and new relay clients. (`cli/src/team/relay.ts`, `TeamRelayPublisher.start`, `installedCodexVersion`, `prepareCodexHome`; `cli/src/superTabs/service.ts`, `createSuperTabsService`.)
6. **Migration and rollback:** there is no database migration. Stopping or withdrawing the publisher removes `relay.json`; closing the relay removes its in-memory grant state. A refresh writes back to the existing owner credential store. The repository does not describe a rollback procedure for a partially upgraded owner and Team daemon. (`cli/src/team/relay.ts`, `withdrawTeamRelay`, `TeamRelayPublisher.close`; `cli/src/lib/ownerSubscriptions.ts`, `refreshClaude`, `refreshCodex`.)
7. **Audience:** on macOS, the handoff ACL grants read access to the configured Team account and the owner. The relay separately requires a valid per-guest token and binds to loopback. The agent process receives the token in its own environment. The code does not mediate what a process running as the Team account can subsequently do with its own environment. (`cli/src/team/relay.ts`, `publishTeamRelay`, `readTeamRelay`; `cli/src/lib/subscriptionRelay.ts`, `startSubscriptionRelay`, `presentedToken`; `cli/src/team/relay.ts`, `teamRelayLaunch`.)
8. **Identity:** provider requests run through the owner's daemon using the owner's provider sign-in; Claude Code and Codex run as the Team account. An engine signed in under the Team account uses that sign-in instead of the relay. No owner's OS login or provider credential is copied into the Team account. (`cli/src/team/relay.ts`, `TeamRelayPublisher.pass`, `teamRelayLaunch`; `cli/src/lib/ownerSubscriptions.ts`, `createOwnerSubscriptions`.)
9. **Failure:** publisher errors are logged and checked again on its next pass. Missing/invalid relay tokens get 401; a missing owner sign-in gets 503; an upstream/network exception gets a generic 502. Refresh failure returns no fresh credential, and the upstream response is returned. A failed Codex model-list fetch keeps its old cache. (`cli/src/team/relay.ts`, `TeamRelayPublisher.tick`, `TeamRelayPublisher.pass`; `cli/src/lib/subscriptionRelay.ts`, `handle`; `cli/src/lib/ownerSubscriptions.ts`, `postToken`; `cli/src/team/relay.ts`, `prepareCodexHome`.)
10. **Platforms:** the Team-account relay is implemented for macOS, Linux, and Windows, with platform-specific handoff paths and ACLs. `/Users/Shared` and the Keychain details above describe macOS. (`cli/src/team/layout.ts`, `teamLayout`; `cli/src/team/relay.ts`, `publishTeamRelay`, `publishWindowsTeamRelay`, `setfaclGrant`; `cli/src/lib/agentCredentials.ts`, `readClaudeKeychain`.)

## Open questions

- `CODEX_UPSTREAM` and `ownerSubscriptions.ts` mark Codex's request route, refresh endpoint, client id, and scope as assumed rather than verified. The code comment says a Codex custom provider asks `/responses`; the Team account asks `/codex/models`. The actual vendor contract and its compatibility across provider versions are not established by this repository. (`cli/src/lib/subscriptionRelay.ts`, `CODEX_UPSTREAM`, `handle`; `cli/src/lib/ownerSubscriptions.ts`, `CODEX_TOKEN_URL`, `CODEX_CLIENT_ID`, `CODEX_REFRESH_SCOPE`.)
- The refresh lock coordinates relay processes that use this implementation. It does not establish whether Claude Code or Codex writes the same credential store concurrently in a way that can race between the relay's re-read and write. The code re-reads after lock acquisition, but does not do a compare-and-swap when writing. (`cli/src/lib/ownerSubscriptions.ts`, `refreshNow`, `refreshClaude`, `refreshCodex`, `writeKeepingMode`.)
- The code does not state a supported concurrency, request-rate, or model-list-size limit, nor a metric that warns before one is reached. It does not specify how an older Team daemon handles the handoff beyond the owner's refresh attempt. (`cli/src/lib/subscriptionRelay.ts`, `handle`; `cli/src/team/relay.ts`, `TeamRelayPublisher`.)
- The code prepares the model list before Codex launch, but does not guarantee that the provider will continue offering every cached model for the duration of a session. A failed fetch leaves the previous cache, so whether a stale model causes a startup prompt depends on Codex behavior outside this repository. (`cli/src/team/relay.ts`, `prepareCodexHome`, `dropUnofferedModel`.)
