## Design

- Growth: the existing private WeakMap retains one already captured fact array and version per live observation. It admits no new persistent data, timer, service, dependency or core file. Groups remain bounded to 32 observations and 256 facts; standalone observations and the existing overall preparation bounds remain unchanged.
- Concurrency: every invocation has a fresh budget and device map. Forward facts then reversed facts with full selected leaf versions remain synchronous. The existing observation revision still refuses any mid-fence replacement. No locks or cross-invocation validity are added.
- Read cost: share the existing two fresh route passes for fixed absent leaves and mixed existing/absent groups. A single absent leaf uses the same fence so it does not reconstruct a route then read the leaf a third time. Existing single-file behavior remains unchanged.
- Scale: current group limits and operation deadline remain. Over-limit, conflicting, custom or incomplete-parent observations retain the original fallback. No unbounded list or recursive discovery is introduced.
- Compatibility: no wire/schema/backend/client change. An absent leaf changing to a file, directory or alias still refuses. Existing ancestor/alias identity and full file version checks remain. Another destination may create ordinary previously absent parents through the unchanged incomplete-parent path.
- Migration and rollback: none; a revert changes only verification work. All original observations and publications use the same objects and disk layout.
- Audience and identity: only the same captured account-owned native settings; no new reader, login, authority or logged content. The compiler receives only metadata registered after inspectHookFile's initial successful verification.
- Failure: no write or publication without current file, route, dependency and owner proofs. Missing root evidence, conflicting facts and expired work retain existing named refusals. A new leaf alias is refused with the hook alias reason; on Windows or an unresolvable POSIX alias this replaces the previous route-level refusal. Both error classes are handled identically by the hook callers. No durability flush, source export or descriptor custody is removed.
- Platforms: shared TypeScript on macOS/Linux/Windows. The existing platform version rules and actual Windows process handling remain unchanged. Native Windows validation is explicitly deferred by the user.
