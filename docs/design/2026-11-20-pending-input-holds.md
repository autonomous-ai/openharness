# Preserve untyped input through pane holds

The packaged lifecycle test drops a queued ordinary message when the person clears a draft. Binding records the draft as identityHold and advances evidenceRevision. The input retry treats that current presentation change as replacement authority and discards the message before a byte was typed.

## Design

Keep the effect-time session fence unchanged. Only after an OpenClaw not-started pane refusal, at a retry boundary with no effect running, allow the same pending intent to acquire fresh authority. Match all previously captured binding fields except the changing hold/revision, preserve the engine state folder and local mode, and require an absent or known recoverable pane hold. Unknown identity/store holds and remote-machine holds refuse. Revalidate the selected native runtime, then require the exact fresh row and original caller/state still current before replacing this operation's snapshot. Actual paste/Enter continues using the unchanged strict fence. A short hold entirely between retry readings can renew only through this same fresh validation; a revision alone never grants an effect.

No new queue, timer, persisted state, dependency, process, public protocol, account identity or telemetry. The existing bounded pane/lease retry spends validation time in its original deadline. The ordinary successful path gains no native probe. Original session, process, pane, folder, caller cancellation and all unknown holds still revoke. Add regressions before changing code, including a hold wholly between retries and mutation during fresh validation. Rollback is code only. Shared TypeScript affects macOS/Linux/Windows; native Windows remains user-deferred. Existing runtime-cost and extraction holds remain open.

Independent review found that a hold can change during a retry's native or screen read, before any write. A proven not-started caller/terminal revocation after a pane refusal returns to that same bounded pane retry. Possibly executed input never does. A general lease refusal cannot renew a binding, even after a previous pane wait. Keep restored-launch lifecycle ownership separate from the replaceable binding snapshot, checking it before and after validation and at each effect. Require transcript interpretation holds absent both when selecting fresh authority and after validation; revision changes cannot bypass them. An initial state-folder discovery, like a later folder change, conservatively refuses the old intent: authority over an unknown folder does not authorize a new one. The replacement/folder regression covers that choice.

The rebuilt packaged test then exposed a distinct presentation race: retry preflight claimed ownership of any text in the box while it only validated the process or read the screen. Discovery passes overlapping those reads could suppress the person's draft hold indefinitely, although clearing the draft delivered the message. Keep control serialization across the whole attempt, but let the writer signal separately when it passes preflight and starts submission. During a known pane wait, only that submission owns text; native and screen reads do not. Initial writes, active recovery commands and destructive clears retain their existing ownership. The signal is local to the existing input operation, never persisted or sent to a service. Actual submission still owns partially drawn text until settlement. It adds no probe, wait, timer or queue. Source and packaged regressions must cover both preflight visibility and partial-paste protection.
