# Compare the completed checkpoint before exporting again

Status: implementation under validation; independent source and performance acceptance pending. The metadata-only proposal was rejected by independent design review: SQLite can rewrite pages at the same size within a filesystem timestamp granule. A timestamp age threshold is insufficient on filesystems with a different clock. Every original performance and extraction hold remains open.

The measured Close workload exports each database conversation twice. Keep both checkpoint phases and the post-exit native proof. In the second phase only, ask the storage worker to compare the actual version-one export stream with the first completed checkpoint. For a completed checkpoint up to one MiB, an exact match avoids a second stage, flush sequence and publication. Larger checkpoints retain the existing export path. A mismatch or unavailable comparison follows the existing export path, within the same overall deadline.

## Design

- Growth: no new persistent field, cache, process, timer class or dependency. The comparison shares the existing four-operation storage limit, has a one-MiB input cap and uses two 128-KiB buffers; ordinary exports retain their one-GiB cap. A capability-specific bounded snapshot transport uses the existing reader implementation. No directory scan or accumulating list.
- Concurrency: existing serialized Stop and storage admission remain. The worker opens the core-selected checkpoint read-only with no-follow/nonblocking flags, validates its exact inode, owner, mode, link count and bounded size, and compares complete bytes through the same paged export generator. It never writes that file. Core captures a fresh bounded proof of the manifest and history before the request and verifies both, plus native source and request authority, after the reply. A late reply cannot authorize reuse. The worker also binds the manifest byte count to the opened descriptor. Unavailable saved-copy proofs fall back; native source/request authority failures still refuse. A supplied screen is saved on reuse.
- Read cost: only the second Close checkpoint compares. The worker stops at the first differing byte; a complete match must also have exact length and EOF. No vendor row or database parser returns to core. Timestamp equality alone never establishes equal content.
- Scale: comparison and export share the original 30-second deadline. An unavailable comparison can fall back only with the remaining budget. Comparison and fallback occupy one core admission. Worker comparison has a one-second cooperative work budget, checked around each read; expiry returns null normally. Core bounds the comparison transport at two seconds and does not reuse a late reply. The existing 30-second worker watchdog remains for an actual hung operation, including process recycling. A closed request retains worker admission until its actual I/O settles or the process exits. A synchronous SQLite call can exceed the cooperative budget; a slow dirty exit can still spend up to the comparison wait before falling back, reducing the time left. This residual needs explicit measurement, not a larger deadline or an acceptance-threshold change. Profile comparison reads, export count and Close CPU/wall cost; do not claim gains from source size.
- Compatibility: add one private storage read request, preserving the existing version-one export request and response. A new storageCompare capability gates the new method. An older worker answers the existing capability request without this field and is never sent the unknown method; core falls back to export. Existing manifests and checkpoint bytes are unchanged; clients and backend are untouched. HarnessOS/older-master inline compatibility delegates through its existing door. If off-thread SQLite is active, comparison returns unavailable and ordinary export is used: its coalesced reads cannot safely be reset synchronously. In the isolated worker, only the selected store's cached native handle is dropped before comparison, ensuring a fresh read even when an immutable cache entry has identical coarse timestamps. No other store is invalidated.
- Migration and rollback: none. Removing the optimization restores unconditional after-exit export; saved data is identical.
- Audience: existing owner/local/internal-only worker checks and snapshot transport connection fencing. Requests carry only core-selected source and checkpoint paths/identities, never caller-supplied SQL. Replies are bounded booleans; errors and logs contain no content or paths.
- Identity: same local account and captured session. The comparison grants no publication or process authority. Every native proof, cancellation, stage handoff and publication fence remains.
- Failure: mismatched, truncated, changed, replaced, linked, aliased or unreadable checkpoint files do not justify reuse. Unavailable/invalid worker replies get a named diagnostic and the existing export fallback if time remains. A dirty native source still refuses through its ordinary proof. Empty OpenClaw output does not match an existing nonempty checkpoint. No partial comparison counts as equality.
- Platforms: shared TypeScript on macOS/Linux/Windows; no new process-launch path. Native Windows validation remains user-deferred. Windows no-follow/owner semantics retain the existing storage conventions and need model coverage.

## Selected validation

The initial five quiet-exit tests fail with two exports, while all changed-source controls pass (`20261120T141326.775270Z-66663`: five failed, 61 passed). Update their fixture to supply the real comparison seam; keep the tests about completed content, not timestamps or callback omission.

Before implementation, add worker controls for exact byte equality, same-size changed rows with unchanged stat timestamps, chunk boundaries, short reads/EOF, size limits, cancellation, read-only descriptors, inode/alias/hard-link/mode/owner refusals, unreadable stores and empty OpenClaw history. Add core/store controls for manifest/history/source changes during the reply, old-worker fallback, invalid/stale replies, four occupied operations, deadline sharing, no stage allocation on equality, and normal export/publication on mismatch. Existing before/after callbacks stay intact. Run affected storage/Close/Stop/checkpoint suites, full required coverage and types, independent source review, then the unchanged production Close/Resume workload against the original baseline. No acceptance by rerunning unchanged code or adjusting thresholds.

## Review corrections and evidence

The first independent design review held metadata-only reuse (141215.751537Z-65640). The second held the unbounded comparison design (141852.371744Z-71428): late mismatch could consume the export deadline; older-worker behavior needed proof; saved-copy failures needed separation from native identity failures. The bounds, capability gate, single admission and proof separation above address those findings; the reduced remaining budget is an explicit residual.

A real SQLite regression (143231.753652Z-83809) reproduced a false match from a cached immutable handle after a same-size row update with unchanged coarse cache timestamps. Both it and the inline-cache control failed before the per-store fresh-read correction. Source review must include this correction and the actual SQLite reader, not assume connections are uncached. All existing performance and extraction holds remain open.
