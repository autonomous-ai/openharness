# Keep current OpenClaw fixes outside the database-reading core

Current main `a59ba98` includes OpenClaw first-task durability, composer retry and Close truth fixes. The refactor must preserve those behaviours without restoring Device input state or SQLite reads in the session-owning process. The existing shared writer retains current-generation checks, queue priority, request correlation, cancellation and original expiry. The new first-task typed marker follows the main-branch design in `docs/plans/2026-11-20-openclaw-followups-design.md`.

## Design

- Growth: no new persistent state beyond current main. The existing four-storage-operation cap also covers the new Boolean observation. Binding still reads at most four recent keys per pass, sequentially with its existing one-second outward wait and one outstanding read per agent.
- Concurrency: registry transitions keep the refactor's owner/current proof and durable receipt semantics. The input controller owns one writer for all callers; worker responses retain current connection generation and bounded admission.
- Read cost: move current main's indexed `LIMIT1` user-row query into the existing engine-others storage process. Core sends a bounded captured session and timestamp interval, and receives true/false/null only. No SQL or returned conversation text crosses the boundary.
- Scale: four shared storage slots, bounded request/reply bytes, five-second worker watchdog around a one-second SQLite subprocess/read-thread deadline and 250 ms native lock wait; timed-out actual work retains admission until it settles, and the worker's existing recycling policy handles a frozen read. Missing, malformed, disconnected or stale replies stay unknown; no inline fallback after an isolated failure.
- Compatibility: extend the private storage version1 request set. An old worker without the new request returns unknown until replaced; no public client or backend contract changes. Explicit no-master/older-master inline composition uses the same worker implementation through the existing inline door.
- Migration and rollback: no additional record or migration; keep main's firstTask/firstTaskTyped parsing and transitions alongside the refactor's asynchronous persistence guards. Both existing source histories remain recorded in the merge.
- Audience and identity: only authenticated owner/local core callers, no outside connection, unchanged own-account state; fixed SQL only. Closed rows never reuse the former process pid. The default missing store is unknown when the TUI's folder is unconfirmed.
- Failure: invalid or unavailable observations remain null and produce a fixed storage diagnostic; the existing waiting/Close state consumes that unknown. Invalid request fields are refused. Preserve retained native location/config proofs for Close; the optional user-row observation verifies the selected config before and after its read and returns unknown if that proof changes.
- Platforms: shared TypeScript, existing macOS/Linux worker and explicit inline compatibility. Native Windows validation remains user-deferred. No new process, runtime dependency or core-loaded file.

## Validation selected before integration

Write boundary tests before implementation: real core-to-worker method and captured snapshot, bounded true/false/null decoding, isolated failures with no fallback, stale connection, shared admission and timeouts; worker private-caller/field/range checks, no SQL field, nullable Boolean reply and actual-work retention after cancellation. Preserve main's real SQLite/time-bound/unknown-default fixtures in the worker layer. Run old and new input, binding, registry first-task, Close, architecture and full required core coverage checks. Run private OpenClaw end to end, independent combined source review and affected hot-path comparisons before release. Existing original-baseline performance holds remain.

## Review corrections

The independent combined-source review held the merge for registry retype ownership, adoption sharing a pending delivery's receipt, adoption during control/cancel, read/export contention, overlapping clears, and withdrawal after submission. These are correctness requirements, not exceptions to isolation.

Retyping checks the exact text and captures owner plus launch before the registry transaction wait. All first-task transitions retain that launch guard. Adoption returns an untyped operation to the existing queue with its original receipt, caller and expiry; its still-running preflight loses permission to write or publish a second outcome. Adoption refuses while a control lease or cancel holds the pane. One existing clearing flag covers the whole durable untype/read/keys/retype interval, and submit checks defer throughout it. Submitted handoff claims cannot be withdrawn. Binding reads prior keys sequentially and stops when its original one-second outward budget ends; a poll therefore occupies at most one storage slot. SQLite receives a one-second timeout and bounded result size, strictly inside the five-second worker watchdog. An unconfirmed default folder supplies no positive or negative ownership evidence.

A Stop retires an already handed-over first task's durable mark and forbids its re-adoption; a pending first-task write retains its claim as caller authority. A matching turn may also retire the exact text from its untyped row after a clear. Messages returned from already chained writes retain one in-memory admission number, so first-task priority does not reverse the messages behind it. This adds one counter per controller and one number per existing bounded request, with no new queue, timer, persisted data or public field.
