# Harness Pro: app icons and card colours in the firmware (item E) — design

Date: 2026-11-20. Item E of [the Pro parity split](2026-11-20-pro-parity-split.md) (sections 2, 3, 5). Branch
`feat/pro-app-icons`. Firmware only: `devices/harness-pro/firmware` plus its source art; nothing in `cli/`.

## Goal

The Pro's Apps screen (item C) draws one card per app: the app's real icon on a card in the app's own colour. This item
bakes those icons and colours into the firmware, as the engine logos are baked, behind the API fixed in the split doc
section 3. An app with no icon gets `NULL` and item C draws its name on the Pro's own dark card.

Done when: `pod_app_style("vscode")` returns a 72 px and a 44 px icon and a two-colour gradient that white ink reads on at
4.5:1 or better; `pod_app_style("nope")` is `NULL`; the host tests and the ESP-IDF build pass; the image stays well inside
`ota_0`.

## What exists

- `scripts/pod_gen_logos.py` reads `.github/assets/engines/<engine>.png` (512×512 RGBA), crops each to its alpha box,
  pads it square, resizes with LANCZOS to 44 and 72 px and writes RGB565 (native order) + alpha8 arrays into
  `main/pod/engine_logos.{c,h}`. **The output is committed** (not generated at build time like `pro_fonts.c`), with a
  "Generated by … Do not edit." header. `test/test_logos.py` parses the committed `.c` for sizes and a byte budget.
- `test/run.sh` builds every `main/pod/*.c` into the host objects with `-Wall -Wextra -Werror` and runs the Python tests.
- The app ids are `cli/src/cable/hosts/hostDetect.ts` `NAMES`. The ids that get a card here: `orca, herdr, rex, zellij,
  tmux, kitty, wezterm, iterm, terminal-app, ghostty, cmux, vscode, cursor, warp, claude, codex, opencode` (17).
  `harness` (the Tabs side) and `terminal` ("Other") get none.

## Design

### 1. Source art: `.github/assets/apps/<id>.png`

One square RGBA PNG per app id, 512×512 or the vendor's largest when smaller (kitty 256, Warp 196; at least 128 px, never upscaled), the app's **official app icon** (the full icon, its rounded tile included, not a bare
glyph: the card shows the app as the person knows it from their Dock). Sources, in this order:

1. The vendor's macOS app bundle (`Contents/Resources/*.icns`, its 1024 px representation, scaled to 512 with `sips`):
   the mockup measured its colours from exactly these. Installed on this Mac: ChatGPT (`com.openai.codex`,
   `icon-chatgpt.icns`, the ChatGPT icon, not the Codex one), Claude, Cursor, Herdr, iTerm2, Orca, VS Code, Terminal.
2. Otherwise the vendor's own published file: the app icon in its official repository, pinned to a commit (Ghostty,
   kitty, WezTerm, Zellij, tmux, cmux, opencode), or the icon its site declares (`apple-touch-icon`, Warp).
3. tmux: its official `logo/tmux-logomark.svg`, pinned, rasterised to 512 with `rsvg-convert`.
4. None found (Rex): the app is left out and shows its name only.

`.github/assets/apps/README.md` records, per file: the source (bundle id and version, or URL and commit), the date, the
source size and the upstream file's SHA-256, plus the engines README's nominative-use note ("third-party marks, no
endorsement; do not recolour or redraw; a mark its owner wants removed comes out"). Downloads go into an empty scratch
directory and are read only by Pillow; nothing downloaded is run. No personal content in the files (icons only, metadata
stripped by re-encoding with Pillow).

### 2. Generator: `firmware/scripts/gen_app_icons.py`

Pillow only, no font. Runs on macOS and Linux. Reads with `tobytes()` (not `get_flattened_data`, which older Pillow on CI
lacks).

For each id in a fixed `APPS` list (the 17 ids above, in `NAMES` order) whose PNG exists:

- **Icon:** the icon's bounding box of alpha ≥ 128, padded square with transparency, resized with LANCZOS to 72 and
  44 px; alpha below 64 is cleared so the macOS drop shadow does not leave a grey haze around the tile on a coloured
  card. RGB565 native order + alpha8, as `pod_gen_logos.py`.
- **Measured colour** (from the 512 px source, opaque pixels only, alpha ≥ 250):
  - *Saturated* pixels: HSV saturation ≥ 0.35 and value ≥ 0.25. When they cover ≥ 10 % of the opaque area, the measured
    colour is their most frequent exact colour ("the largest saturated colour").
  - Else the *dark mark*: the most frequent exact colour among pixels with luma below 128.
  - Else (an all-light icon): the Pro's own dark, `#55555C` (`PH_TINT_OTHER1`).
- **Card colour:**
  - A near-black measurement (relative luminance < 0.012, e.g. `#000000`, `#141414`) is lifted to the **charcoal**
    `#3A3A3F`, the mockup's dark gradient top.
  - Darkened only as far as white needs: scale R, G and B together in 1 % steps until white on the **RGB565** colour
    (decoded back to 8 bits) is ≥ 4.5:1. A colour that already passes is kept as it is.
  - `card_top` = that colour in RGB565; `card_bottom` = the 8-bit `card_top` halved per channel, then RGB565.
- Writes `main/pod/app_icons.c` and `main/pod/app_icons.h` with the "Generated by scripts/gen_app_icons.py from
  .github/assets/apps/*.png. Do not edit." header; the `.c` has a comment per app with its measured colour and the
  contrast of both ends. `--check` regenerates in memory and fails when the committed files differ (the
  `gen_ph_spark.py --check` pattern), so art and output cannot drift.

Prototype numbers (this Mac's bundles): measured VS Code `#1F9CF0` → top `#1879BD` (4.66:1); Claude `#D97656` → `#AD5D42`
(4.75:1); ChatGPT `#2C2E3A`, herdr `#303438` kept; Orca, iTerm2 `#000000`, Terminal `#141414`, Cursor `#14120B` → charcoal.

### 3. API: `main/pod/app_icons.h` (exactly the split doc's)

```c
#pragma once
#include <stdint.h>
typedef struct { const uint16_t *rgb565; const uint8_t *alpha; uint16_t size; } pod_app_icon_t;
typedef struct { const pod_app_icon_t *icon72, *icon44; uint16_t card_top, card_bottom; } pod_app_style_t;
const pod_app_style_t *pod_app_style(const char *app_id);   // NULL for NULL, an unknown id or an app with no icon
```

`app_icons.c` holds a `static const` table and a linear `strcmp` lookup (17 rows). Nothing else is exported. One line
`"pod/app_icons.c"` in `main/CMakeLists.txt` after `"pod/engine_logos.c"`. `run.sh` already compiles every
`main/pod/*.c` with `-Werror`.

### 4. Tests: `firmware/test/test_app_icons.py` (added to `test/run.sh`)

Red first (no generator, no `app_icons.*`), then green:

- every app with source art has a 72 and a 44 px icon in `app_icons.c`, and every listed id without art is named in the
  README as left out; `harness` and `terminal` have no row;
- every icon's alpha is non-empty (some pixel ≥ 128 at both sizes);
- white on `card_top` and on `card_bottom` is ≥ 4.5:1 for every app (RGB565 decoded to 8 bits);
- darkened no further than needed: `card_top` is the measured colour (as RGB565) or its contrast is < 5.0:1;
- `card_bottom` is `card_top` at half brightness (± 1 RGB565 step per channel);
- the mockup's five: measured Orca `#000000`, VS Code `#1F9CF0`, ChatGPT `#262834`, Claude `#D97757`, herdr `#303438`,
  each channel within ± 8 (the mockup's own measuring code is not published: on the same bundles this rule gives
  ChatGPT `#2C2E3A` and Claude `#D97656`); Orca's card is the charcoal;
- the generator's `--check` passes (committed output matches the art);
- byte budget: px + alpha of all icons ≤ **400,000 bytes** (17 × (72² + 44²) × 3 = 363,120 at most); printed, as
  `test_logos.py` prints its 100 KB figure;
- `pod_app_style`: a small C program compiled with `cc` against `app_icons.c` (the test builds it in a temp dir) checks
  `NULL` for `"nope"`, `""`, `NULL`, `"harness"` and `"terminal"`, and a non-NULL style with `icon72->size == 72`,
  `icon44->size == 44` for `vscode`.

Also: `bash test/run.sh`, `python3 test/test_tree_isolation.py`, and the compile with ESP-IDF 5.5.4
(`idf.py -B build -DPROJECT_VER=0.0.99-pod build`), the image size recorded in the PR against
`devices/harness-pro/docs/size-baseline.txt` (about +0.36 MB on ~3.98 MB of the 8.26 MB `ota_0`).

## Out of scope

Drawing (item C), the model and cable (item B), the daemon (item A), the round dial, any runtime scaling, a hosted icon
service. No flashing, no serial port, no release.

## Platforms

Build-time only. The generator and tests run on macOS and Linux (CI). Sourcing from app bundles is a one-time manual
step done on a Mac and recorded in the README; regenerating from the committed PNGs needs no Mac. Windows: the generator
is plain Python and Pillow; not exercised (the firmware is built on macOS and Linux CI).

## Decisions (approved by the PM, 2026-11-20)

1. Icons from the vendors' macOS app bundles where installed (a read-only copy; the apps are never modified), else their
   official repo (pinned to a commit) or site files; Rex left out (name only). Every source in the README.
2. This rule wins over the mockup's hand-measured values: the five match within ± 8 per channel; the ChatGPT and Claude
   differences are accepted and noted in the README.
3. Charcoal `#3A3A3F` (the mockup's gradient top); near-black (luminance < 0.012) is lifted, which also lifts Cursor,
   iTerm2 and Terminal, whose icons are black tiles.
4. Committed generated output with a `--check`, like `engine_logos.c` (not generated at build time).
