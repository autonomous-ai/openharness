# Personal coding memory MVP

Status: bounded review handoff prepared; live acceptance remains open. Scoped by
the user on October 3, 2026. This is the current delivery
milestone. The broader council, architecture and benchmark plans remain a roadmap;
their complete research programs are not prerequisites for this review milestone.

The finish line is a reviewable experience that demonstrates useful memory about
how this user builds Harness, with concrete evidence. It is not a claim of perfect
or generally validated memory. The user decides on further investment after review.

## Scope and acceptance

One user, one machine, the Harness coding project, and the existing Companions DSH.
Keep the viewer left and the actual agent terminal right. Use the existing
experimental setting and the model selected for that DSH. Memory belongs to the
Harness profile/project and remains independent of avatar and agent framework.

1. **Learn something real.** Produce three to five accurate, actionable memories
   from already consented real conversation evidence. Every displayed assertion
   needs an inspectable source quote and appropriate project/condition boundaries.
   Do not fill a quota with speculation or turn a suggestion into a settled decision.
2. **Continue learning.** Demonstrate one new eligible interaction moving through
   capture, extraction and storage. A history import or hand-seeded record alone
   does not establish automatic learning. Show a truthful waiting/error state if
   the selected model cannot run.
3. **Help on a later task.** Demonstrate a fresh coding session receiving a relevant
   memory and using it correctly, without repeating the preference in that task.
   Check one unrelated request does not receive that memory. Keep the shared
   storage/recall contract across existing framework adapters; exhaustive native
   version and lifecycle certification is deferred.
4. **Make it inspectable and editable.** Show memories and evidence in the existing
   Memories viewer. Verify a correction affects later recall and a forgotten memory
   is absent from later recall. Do not claim old conversation context was erased.
5. **Hand over a reviewable result.** Provide the exact build/source revision, a
   short walkthrough, and a pass/fail account of these behaviors. Distinguish
   delivery, correct use and user confirmation. Do not present synthetic fixtures
   as learning from real sessions.
