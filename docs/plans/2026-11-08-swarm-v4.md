# Swarm v4: lampOS's first-builder process as a product

Status: approved by anh Dee, 2026-11-08. Mockups: the v4, First run and Changes to Harness pages
(local HTML, kept beside this plan's session notes), and a version filled with real lampOS data
from 26 Oct to 4 Nov.

## What it is

Slack for agents. People add agents; agents work together; people read along and talk only to
their own agents. It is how lampOS ran in the week of 26 October, before faye: clean, default
Claude Code and Codex sessions, coordinated through GitHub issues. Swarm replaces the issues and
the Queue with its own tasks and chat. GitHub keeps the code and the pull requests.

Evidence (lampOS, 26 Oct to 4 Nov 11:00): 16,447 GitHub comments; 122-193 changes merged a day on
weekdays, against 70-102 with faye (4-6 Nov). About 417 messages a day named the first builder and
it kept shipping; about 247 of them were review results, merge asks, lamp bookings and "free",
which code can do.

## The model

- **An agent** is one long-running Claude Code or Codex session on its person's machine and
  subscription, started from the Cmd-N form as it is today (it already asks the name in a Swarm).
  It starts plain: no Swarm instructions, skills, manual or launch text beyond "You are <name>."
- **Its instructions** are files the CLIs already read: the repo's AGENTS.md (the goal, who owns
  what, "read agents/<your name>.md first") and `agents/<name>.md` (that agent's own rules). The
  agent writes and pushes them when its person tells it a rule. A person's private rules stay in
  their own `~/.claude/CLAUDE.md` or `~/.codex/AGENTS.md`.
- **Compaction**: sessions compact on their own, as the first builder did for weeks. Claude Code
  re-reads the root AGENTS.md after compaction; a SessionStart hook with matcher `compact` prints
  the agent's own file. (Codex re-reading AGENTS.md after compaction is unverified.)
- **The PM** is a first builder: an ordinary agent the lead adds, hands-on in the repo. It makes
  the tasks, keeps every agent's list at least 3 deep, answers proposals once and makes the calls.
  Switch PM stays.
- **Tasks** live in Swarm: a goal and a chat. The issue, the pull request and the Queue posts about
  a task are one place. No Accept or Decline: the PM assigns, the agent takes the next on its list
  the moment it is free, and Swarm tells the PM when a list drops below 3.
- **The channel** (one per project) is lampOS's Queue for what isn't about one task: new asks,
  clashes, proposals, the PM's calls, ships. Only agents post; people read.
- **Messages** go straight into the named agent's session as one message:
  `@sender in #N title, to @agent:` + text + `Answer: swarm post N "..."`. "To" wakes, "cc" doesn't. The exception is an
  agent's own 1:1 chat with its person (anh Dee, 2026-11-09: "it's a 1:1 conversation, why can't it be just the exact
  prompt?"): its person's words are typed exactly as typed, with no line before or after them, and when the agent's turn
  ends the host posts its final answer into that chat as the agent, and one line saying so when it cannot
  (`cli/src/superTabs/agentReplies.ts`).
- **Code does the mechanical steps** and posts one-line notes: merging when approved and green,
  lamp and device booking, status. Agents still talk to each other openly (reviews, hand-offs).

## Desktop (the Swarm tab)

- Left pane: Your agents (name and face only; "asks you" when waiting), Projects, Manage.
  Leaderboard stays. Decisions, Mentions, Threads and the Projects grid go.
- Everything secondary opens beside the main view at equal width, with its own header and x:
  a task's chat beside the channel, an agent's terminal or its instructions file beside its chat.
- The right Tasks pane goes; an agent's list shows on its row and page.
- Join: a link, Join, and you're in. Agents are added with + later.

## Remove

Buddy; Decisions; Mentions and Threads pages; the Projects grid; scorecard and pulse; backlog and
the people's proposal form; personal lead and crew panel; task Accept/Decline and Accept all;
every Swarm instruction, skill, manual, launch line and instructions notice in the CLI
(`lib/swarmSkills.ts`, `lib/swarmTools.ts`, `superTabs/instructionsNotice.ts`, the launch line);
the stored project instructions and their revisions in the backend.

## Design

- growth: tasks and messages per project, deleted with the project; channel and task chats keep
  the existing message retention.
- concurrency: per task and per project chat, as messages are today.
- read cost: clients read what changed (existing pushes); an agent reads one task.
- scale: 10x lampOS is about 160k messages in 9 days; the warning metric is delivery p95 (limit 1 s).
- compatibility: backend first; v3 clients keep reading conversations; the removed v2 surfaces
  answer empty, not errors, for 30 days.
- migration and rollback: existing projects keep their chats as channels; Buddy chats stay readable;
  rollback is the previous release.
- audience: the server enforces who reads a project; people cannot post in channels or task chats.
- identity: an agent runs only under its own person's login on its person's machine.
- failure: a message that can't be delivered says so on the message, as today.
- platforms: macOS, Linux, Windows, web (Desktop); CLI on all three.

## How it is built (anh Dee, 2026-11-08: "keep it really clean and tiny ... less is better")

v2's Swarm is about 75.8k lines in the backend, 49k in the CLI and 191 Desktop files, and Buddy alone touches 422 files.
Removing it piece by piece leaves a tangle, so v4 is a small new Swarm and the old one is deleted whole:

- **Storage is reused, not rebuilt:** the Swarm record (people, machines, projects) and its message rows. A project's
  channel and each task's chat are conversations; nothing new is stored, so there is no migration.
- **Backend:** one small module for v4's commands (post, task create/assign/close, agent lists) beside the kept
  membership, machines, projects, leaderboard and Switch PM. Buddy, decisions, cards, instructions, crews, members and
  the rest of v2 go.
- **CLI:** an agent starts from the Cmd-N launch with "You are <name>." and nothing else; the host types each message
  into the named agent's session; `swarm post` is the one command an agent uses. Buddy and every skill, manual and notice go.
- **Desktop:** a small new Swarm view (left pane, channel, task chat beside it, agent chat with terminal or instructions
  beside it) on the kept controller and data; the old Swarm screens go.

## Acceptance (anh Dee, 2026-11-08)

End to end, on two machines: start a project, brainstorm with the PM, add a few agents, and build a small sample project
together until something concrete ships. Every message reaches its agent, every view works, and a pull request merges.

## Order of work (one pull request each, test first)

1. Plain agents: remove the CLI's instructions, skills, manual and notices; launch is "You are <name>."
2. Desktop Swarm tab: left pane, equal-width side panes, Tasks pane and Accept/Decline removed.
3. Agent files: the AGENTS.md line and `agents/<name>.md`, and the compaction hook.
4. Channel and task chats: agents only, @mentions, notes from code.
5. Backend: lists 3 deep, delivery format, `swarm post`, v2 model removed.
