# Desktop 1.3.89 audit: every Swarm v3 screen and flow

Task #4436. Build: tag `v1.3.89_desktop` (610ccb0), the first with Cmd-N Lead/Member, Tasks as cards with Approve,
the Buddy menu and the PM crown with its project.

## How it was checked

- Offscreen widget tests on the tagged code, with a memory store and a fake sign-in, and the Mac's real fonts. Nobody
  signed in, no login was read, and no build was installed.
- The existing shot tests were run, plus throwaway shot tests for each finding (not committed).
- Every finding was traced to the code at the tag; file and line refer to `desktop/lib/` there.
- Covered:
  - Joining a Swarm and bringing your own agent.
  - The left pane: org switcher, Decisions, My agents with Buddy first, crown and project, + New agent, Cmd-N.
  - The middle chat, the Board, a task opened in the middle.
  - The right Tasks pane: cards, Approve and Reject, history and paging.
  - The Buddy menu: Restart with flags, Rename, Remove.
  - An empty org.
  - Light and dark.
  - Windows 1500, 1100 and 880 wide. 880 is the smallest the real window allows (`core/desktop_window.dart:36`).
- What a real window adds: native title bar, real hover and focus, the system font renderer. Some shots at 820 and 700
  show worse than a person can get.
- Not findings:
  - Inline code drawn as solid blocks: the test runner lacks the terminal font.
  - The striped or red bars in some shots: Flutter's overflow warning, which is itself a finding where noted.
  - The grey right pane reading "Tasks (v3)" or "Tasks pane (stand-in)": a test placeholder.
- Platforms: the screens are shared Flutter code, so every finding applies to macOS, Windows and Linux. Shots are from
  macOS.

Screenshots are in [2026-11-07-desktop-1.3.89/](2026-11-07-desktop-1.3.89/).

## Ranked findings

Ranked by how much a person would notice: first what blocks or misleads, then rough edges, then polish.

### 1. Clicking a card on the Board opens nothing (High)

- **Where:** the Board.
  - `super_tabs/view.dart:3550` `_openTask` → `_openConversation` (`:2304`) → `_showBoardOf` (`:283`) selects the
    task's chat but keeps the Board in the middle.
  - With Tasks on, the right pane is always the Tasks pane (`view.dart:6331-6339`), so the chat has nowhere to show.
- **What a person sees:** the card turns grey and nothing else happens.
- **Should be:** the task opens in the middle under its task header, as a Tasks card already does
  (`_openPersonalTask`, `view.dart:3557`).
- **Screenshots:** [light](2026-11-07-desktop-1.3.89/01-board-card-opens-nothing-light.png),
  [dark](2026-11-07-desktop-1.3.89/01-board-card-opens-nothing-dark.png). The selected card is "One tag per ask".

### 2. The first "Bring agent" always fails for a new joiner (High)

- **Where:** the bring-agent form after Join Swarm, `super_tabs/join/bring_agent.dart:81-85`.
  - For a computer the Swarm doesn't list yet, the computer's Harness answers the first prepare request with
    "preparing" (`cli/src/superTabs/contribution.ts:150-170`).
  - Desktop treats "preparing" as a failure.
- **What a person sees:** their first click in the Swarm ends in red, "Your agent's folder is still being prepared.
  Try again to check it.", and they have to click again. If the folder takes longer, they get the same error again.
- **Should be:** keep "Starting your Buddy…" on screen and ask again every second until it is ready. Adding a computer
  already works this way (`super_tabs/machines.dart:287-321`).
- **Screenshots:** [light](2026-11-07-desktop-1.3.89/02-bring-agent-first-click-light.png),
  [dark](2026-11-07-desktop-1.3.89/02-bring-agent-first-click-dark.png).

### 3. One refused Approve locks every card in the Tasks pane (High)

- **Where:** `super_tabs/tasks/personal_tasks_pane.dart:86-99`, `:166-172`, `:248-258`.
- **When:** the server refuses an Approve or Reject: the suggested agent changed, the task is archived, or no access.
- **What a person sees:**
  - "The change is not confirmed. Retry to check it."
  - Every Approve, Reject and the Auto approve/Review menu stays greyed out.
  - Retry sends the same refused command again, forever.
  - The server's own sentence is never shown in the pane.
- **Why:** the pane keeps its own copy of the action, which is what disables everything, while the controller has
  already dropped it.
- **Should be:**
  - Show the server's sentence.
  - On a definite refusal, drop the action, enable the buttons and read the task again.
  - Offer Retry only when the answer was lost.
- **Screenshots:** [after the refusal](2026-11-07-desktop-1.3.89/03-refused-approve-first.png),
  [after three Retries, still locked](2026-11-07-desktop-1.3.89/03-refused-approve-locked.png).

### 4. Tasks show the wrong status words and marks (High, misleading)

- **Where:** `super_tabs/tasks/personal_task_card.dart:229-243`, used by every card's mark and by the task header

- **What a person sees:**

  | Task is | Header says | Card mark |

- **Should be:** every backend status in the Board's own words: Ready for review, Planned, Cancelled, Stuck, Done.
