# Pro Player · Studio

Status: design, approved in conversation 2026-10-09 · branch `dev/firmware-pro-studio` (from `dev/firmware-pro` `07ea2fd55`)

## Goal

Re-skin Harness Player 1 on the Pro (720 × 720, ESP32-P4) to the approved Studio mockup
(`devices/harness-device/firmware/mockup/pro-player-studio.html` and `mockup/pro-player/studio-*.png`).
Player 1's screens, gestures and flows stay as they are.

The redesign adds one structural change: a horizontal tab bar.
- **Recent** is pinned first. It shows the `player.library` list.
- The desktop's tabs come next. Tapping one switches the desktop's active tab, as Player 1's tab switcher
  does now. The device then shows that tab's agents laid out as the panes are on the desktop.
- The **Settings** gear is pinned last.

Success:
- Every screen in the mockup renders on the device and matches the mockup's layout, colours and type
  hierarchy. Host raster exports are compared side by side with the mockup before any flash.
- A tab with 1 to 16 panes shows them in the desktop's arrangement.
- Anything else falls back to the list: a tab with more panes, an older daemon, or an expired layout.

Out of scope:
- Moving the Player protocol to `main`. That is a separate spec later.
- Layouts of tabs other than the active one.
- The Living / character interface.
- Battery work.

## Decisions

| Question | Decision |
|---|---|
| Scope | Firmware, daemon and desktop, all on a branch from `dev/firmware-pro` (option C: prove it here, then a separate spec brings the protocol to `main`) |
| What a tab chip does | Switches the desktop's active tab (Player 1's existing command), so only the active tab's layout is needed |
| Recent | The existing `player.library` (New Tab order, paged six rows, status, engine, age). No new message |
| Pane layout | New `player.layout`, the active tab's pane rectangles in thousandths, at most 16 |
| Fonts | Inter and JetBrains Mono (OFL), not SF Pro / SF Mono: the repository is public and Apple's licence forbids redistributing SF |
| The 180° panel turn | Kept in the strip push (`display_habitat.c`), independent of the UI |

## Screens

| Mockup | Firmware view |
|---|---|
| Recent | `AGENTS`, the library list (`pro_player_library`) |
| Tab with pane tiles | `HOME` on a tab: a new layout view drawn from `player.layout`, the list when there is none |
| Detail, question | `AGENT` / `HOME` with an agent (`pro_player_home`) |
| Answer: choose, review | `QUESTION`, `CHOICE`, `ANSWER_REVIEW` |
| Listening | `VOICE` |
| Settings | `SETTINGS` (`pro_player_settings`) |
| Loading, empty tab, disconnected | the `loading`, `!count` and `!connected` branches of the views above |

The tab bar is drawn at the top of Recent and of the tab view. Its chips are `pro_hit` targets that issue
the existing tab-select command. The bar scrolls horizontally when the chips do not fit; Recent and the
gear stay pinned, and the chips fade into the gear at the right edge.

Tile content follows the mockup:
- name, then machine and engine;
- a `NOW` line with the latest action while the agent is working, or the question with a Review button
  while it waits on one;
- a status row with the elapsed time.

A tile narrower or shorter than about 140 px keeps only its name and status mark. The pane the desktop
focuses has the accent border.

All are RGB565-representable within a step. Type sizes: title 64 bold, list name 31, tile name 27 to 36,
body 24 to 38, mono labels 15 / 18 / 21. Cards are rounded 20 to 22 px with 1 px lines. Chips and buttons
are fully rounded. Status marks keep the desktop vocabulary: the braille spinner (10 frames × 100 ms),
`?`, `✓` and `✗`.

Everything is drawn with the primitives already in the Pro canvas: `ht_pro_rect` with radius, `ht_pro_text`,
`ht_pro_wrap` and `ht_pro_image`. A bordered card is two stacked rectangles. Fonts are generated by the
branch's `generate_fonts.py` with the TTF input changed. The added flash is a few hundred KB inside 16 MB.

## Data: `player.layout`

**Desktop** (`app_state.dart`, beside `playerOverview` / the `app_swarms` frame):
- For the active tab, it takes `Swarm.arranged`, or the default arrangement `PaneGrid` draws when there is
  none.
- Each tile becomes `{agentId, x, y, w, h}` in thousandths (integers 0 to 1000), plus the focused pane's
  `agentId`.
- More than 16 tiles sends no layout.
- It is sent on tab switch, split, divider drag and focus change, coalesced like `app_swarms`.

**Daemon** (`localWsServer.ts` parses it; `cableSession.ts` sends it):
- Validation follows the existing `contexts` rules:
  - `agentId` under 48 bytes and a member of the active tab;
  - integer coordinates 0 to 1000, with `w` and `h` above 0;
  - at most 16 tiles.
- It sends `{ t: 'player.layout', tabId, focus, panes: [{ id, x, y, w, h }] }` only when the dial's
  `hello.features` lists `player.layout`, as `player.library` is gated.
- It does not resend an unchanged layout, and resends on reattach.

**Firmware** (`cable_client.c` → `ui_player_layout()`):
- Every bound is re-checked; a bad frame is ignored and the previous layout is kept.
- The layout expires on a tab change, on disconnect, or when a pane's agent is not in the roster. An expired
  layout falls back to the list.
- `player.layout` is added to `hello.features`.

## Errors and compatibility

The data is additive and optional:
- Older firmware ignores unknown messages, and the daemon never sends one the firmware did not advertise.
- `main`'s daemon, which is what the owner's computer runs today, still drives the new firmware; it simply
  has no library or layout, so tabs show as lists.
- A layout frame that fails validation anywhere is dropped silently, and the list is shown.

## Testing

- **CLI:**
  - `localWsServer` spec: layout validation (membership, bounds, cap).
  - `cableSession` spec: sent only when advertised, deduplicated, resent on reattach.
- **Desktop:** building the layout from `Swarm.arranged` and from the default arrangement, including the
  16-tile cap.
- **Firmware host tests:**
  - parsing and bounds of `player.layout`, expiry and fallback;
  - `test_pro_touch_ui.py` gains Studio fixtures, exported with `HARNESS_PLAYER_PREVIEW` for every
    mockup screen (Recent, 1 / 2 / 3 / 2 × 2 tabs, detail, question, choose, review, listening, settings,
    loading, empty, disconnected);
  - the exports are compared with the mockup before flashing.
- **On device** (`E8:F6:0A:E7:63:7D`, assigned by the owner on 2026-10-09):
  - flash, verify the boot banner;
  - check each screen and the touch targets on the turned panel.
  - Running it end to end needs the branch's CLI and desktop installed locally. Afterwards `main` is
    restored with `make install-cli` and a desktop rebuild.
