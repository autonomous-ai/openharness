# Poll cost: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cut backend CPU spent on polls: count what polls return, patch the last four whole-reloaded cache entries, and make
the daemon and Desktop stop reads that tell nothing new.

**Architecture:**
- **Backend:** adds counters, extends the delta cache (#2519) to `feed`, `light`, `host:state:{m}`, `host:inputs` and
  `startsOf`, makes the receipt read cheap, and pushes delivery cancels/answers and terminal requests.
- **CLI daemon:** retries held deliveries locally, backs off receipt checks, and slows its other polls behind push leases.
- **Desktop:** reads the open conversation's messages only when its own counters move.

**Tech Stack:** TypeScript (backend Node/Fastify/Prisma-on-Mongo/ioredis; CLI Node), Dart/Flutter (Desktop), vitest,
flutter test.

**Spec:** `docs/superpowers/specs/2026-11-02-poll-cost-design.md` (read it first; it carries the why and the measured
numbers).

- **Spec values:**

  | Value | Where |
  |---|---|
  | Held delivery re-claim at most every 2 min; held agent list every 30 s plus on push | Part 3 |
  | Receipt check back-off 5 s doubling to 5 min; retire on final refusal or after 25 h; `HOST_UNAVAILABLE` from billing is not final | Part 3 |
  | Telemetry settings at start, on local change and hourly; reports every 5 min | Part 4 |
  | Terminal: `__terminal_waiting` push; 8 s fallback poll with the push lease, 3 s without; backend deadline stays 10 s | Part 4 |
  | Fleet machine list 45 s TTL, refresh every 5 min plus on `machines_changed`; window path joins in-flight reads only | Part 4 |
  | Experiment settings re-read only on `desk_changed` with revision 0 | Part 4 |
  | Pro cards follow the `swarm_changed` push lease with a 2 min safety net | Part 4 |
  | Desktop own-receipt refresh by `?messageId=` every 30 s, bounded 10 min (60 min held), for queued, claimed, uncertain | Part 2 |

## Review Focus

1. **A push lost while a delivery is held.** The held message must still be written within 30 s of the pane freeing, and a
   cancel must still stop it. Test: Task 10, "a cancel missed by push stops the retry at the next 30 s read".
2. **Desktop with two Swarm tabs, one off screen.** The off-screen tab's open conversation must not read messages on the
   other tab's changes. Test: Task 15, "a change in another Swarm reads nothing here".
3. **A machine that leaves a Swarm while its `host:state` is held.** Its rows must not keep showing that Swarm's agents. Test:
   Task 5, "a machine whose agents all left derives an empty state".
4. **A daemon restarted with held deliveries and failing receipt entries on disk.** Back-off state must survive or restart
   safely, with no burst of retries. Test: Task 11, "back-off resumes from the journal after a restart".
5. **An older daemon against the new backend.** `__terminal_waiting` and the extra delivery pushes must not break it. Test:
   Task 9, "a frame an older daemon sees is a `__` control frame or a delivery push it already reads".
