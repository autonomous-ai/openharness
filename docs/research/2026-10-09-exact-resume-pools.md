# Complete exact transcript lookup

An explicit resume id used a full `readdir` for Pi and Claude, and a synchronous first-match walk for Codex. A failed later home or truncated walk could be reported as absence; a first match could hide a conflicting transcript. Resume after a crash, Stop capture and Pi Close read these facts in core.

The former-main golden is committed separately in `2cb987e24`. Its 18 observations cover default and moved homes, explicit Codex profiles, missing/unsupported ids, Pi custom ids and colliding workspace encodings. Linux, UTC, fixed time, private homes and abstract workspace realpaths are pinned. Host binaries and optional reader loading are forbidden. The initial recording exposed a random temporary-directory name inside Pi's encoded workspace; the corrected fixture uses a fixed abstract workspace and passed before production edits. The JSON artifact is not re-recorded for the move.

`engines/kit/exactTranscript.ts` streams a complete pool under a shared 4,096-operation/entry budget, at most 64 roots and 64 existing candidate files, and a depth bound. A shared two-second work deadline is checked between operations. Native calls themselves are not cancellable: these are work bounds and change detection, not a hard elapsed-time guarantee. Directory aliases are traversed once but each path's evidence is retained. File aliases count once. Missing locations, directory listings, selected and rejected candidates are revalidated; the final bounded metadata check has no native await and checks a selected file last. The check is not an atomic multi-file snapshot.

Claude retains exact filename authority and requires a readable regular file. Codex checks its declared first record's id before accepting a filename match. Pi keeps the existing id and workspace header checks, including the distinction between unwritten and unreadable conversations. Ambiguous, unreadable, oversized or changing pools hold the lookup. Subsequent calls gather fresh evidence. The optional history APIs and the registry's legacy synchronous repair remain separate work; the saved-home catalog still requires its own freshness and failure audit. This change does not claim that those remaining paths are complete.

Validation selects typecheck, architecture, unchanged exact-resume/session-store/repair/native goldens, affected repair/capture/Stop/binding specs, core/services and harnessd coverage, and serial resume coverage. Private bundled missing/stalled Pi lanes verify Close retains a live session on conflicting files and succeeds after evidence recovers. The touched machine crash-resume lanes and moved-home lane run privately. Assertion-failing wiring mutations and matched CPU/latency/RSS measurements precede independent review and automatic CI. No release.

The correction revalidates current homes and canonical workspace proofs, ties an opened header descriptor to its inspected version, preserves typed holds through checkpointing, and gathers Pi identity before writing the screen. Composed queued Close tests use real native files through capture and checkpoint, retain the same waiting plan for partial and duplicate records, preserve all existing checkpoint bytes, and finish without a new request when evidence recovers. These are safety corrections, not golden re-recordings. The golden fixtures map abstract workspaces to private real directories for canonical identity; the JSON artifacts and healthy answers remain unchanged.

The corrective focused run passed all 369 tests; typecheck independently rejected an inferred test fixture array type. That annotation was fixed before final acceptance. No failed or partial run is represented as a passing gate.

Final synchronous revalidation checks those links before accepting the pool. Three directory-redirection regressions cover root, ancestor and chained-target aliases. The ordinary shared ancestors do not use directory-content stamps, so unrelated activity in the temporary directory is not evidence about this lookup.
