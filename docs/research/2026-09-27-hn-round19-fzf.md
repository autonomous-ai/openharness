## Confirmed remaining findings

No Critical findings or crashes were observed.

### M1 — OR-only queries still omit external conversations

This is the remaining OR limb of round-18 H1, reduced in severity because the negation cases now work.

**Repro:** run `sessions19.py` below. Open C-b s with the demo mock, clear the query, and type `nfc | decimal`. The mock contains `Continue NFC device chat`, whose title matches the first branch, and the billing harness, whose visible detail matches the second.

```text
actual hn:   1/8   Refactor billing service … Invoices now use Decimal …
expected:          billing and Continue NFC device chat
control:     reader → 2/9, including Continue NFC device chat
```

The normal fzf OR model retains either matching row; the key-list reference exercises that model directly. Here `said_terms` drops both OR alternatives and produces an empty index query. `input.rs` then clears the external search rows instead of searching either alternative. The count difference is caused by discovery, not by fzf ranking. Capture: `out/session-03-nfc_|_decimal.ansi`; paired controls are in `out/sessions.log`.

**Suggested fix:** search the necessary alternatives, combine/deduplicate their hits, then apply the complete query before offering them. A query whose only positive terms are alternatives still needs discovery.

### M2 — `search(...)` bindings do not use session search

**Repro:** `sessions19.py`, with:

```sh
FZF_DEFAULT_OPTS="--preview-window=hidden --bind 'ctrl-l:clear-query,alt-f:search(reader),alt-0:first'"
```

Clear the C-b s query, press Alt-f, then compare with clearing and typing `reader`.

```text
Alt-f:         1/8, only the scattered-letter billing match
session_search request count: 8 → 8
Type reader:   2/9, NFC conversation first plus billing
```

A `search(reader)` action correctly leaves the displayed input unchanged; it should nevertheless search the same corpus as typing `reader`. The key-list fzf comparison confirms its filtering behavior. hn's bound action updates `picker.search`, while the index scheduling and hit identity use only `picker.query`. Capture: `out/session-bound-search.ansi`; request counts and the typed control are in `out/sessions.log`.

**Suggested fix:** derive index requests and hit applicability from the effective search expression, while preserving the visible input as fzf does.

FZF_DEFAULT_OPTS="--bind 'alt-m:change-multi+toggle,alt-z:change-multi(0)+toggle'"

The initial screen matches. Both differing snapshots affect the marker and info count only. `bound_actions` receives one `multi` boolean and continues using it after `change-multi` changes the mode. Evidence: `out/actions.log`.

### L2 — Dynamic section labels discard ANSI styling

**Repro:** `actions19.py label-list label-input label-header label-footer`. Example options, with a literal ESC generated portably:

```sh
esc=$(printf '\033')
FZF_DEFAULT_OPTS="--list-border --list-label=before --bind 'alt-l:change-list-label(${esc}[32m green ${esc}[0m)'"
```

Press Alt-l. Text and position match, but hn paints ` green ` with foreground **145**; fzf paints it **2 (green)**. The same result occurs for `change-input-label`, `change-header-label`, and `change-footer-label` (the latter with `--footer=foot`). The four static ANSI section labels work; the dynamic actions remove their SGR with `strip_ansi`. Evidence: four one-row color differences in `out/actions.log`.

### L3 — Removing a negated keyword still joins its OR neighbors

This is round-18 L1, not a new regression.

**Repro:** `edges19.py keyword-or`, same 40 key rows, type:

```text
bindings | !zz $
```

```text
hn:         40/40, all 40 bindings remain
fzf 0.67:   0/40
```

The lines contain `bindings`, but no literal `$`. fzf applies `(bindings OR !zz) AND $`. The extra-keyword fallback drops `!zz` before building its OR groups, effectively admitting rows through `bindings OR $`. The actual captured cells/counts are in the `CASE keyword-or` section of `out/edges.log`.
