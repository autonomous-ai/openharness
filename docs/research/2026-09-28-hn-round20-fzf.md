`/tmp/hnr20fz-review/`; the reader follow-up is in `/tmp/hnr20fz-reader/`.
From a checkout with the existing CLI dependencies and the reference tools:


The drivers refuse an unexpected executable hash or any port outside
**19510–19519**. Every hn invocation uses its copied binary, explicit
`-L hnr20fz…`, matching `--port`, `PORT` and `HN_SOCKET_NAME`, disposable HOME,
and private short `HN_TMPDIR`. TMUX, TMUX_PANE and HN_SOCKET are removed in both
parent and outer-tmux child environments. Every tmux invocation has a private
`-L` name. No default socket, installed hn, real daemon or real harness was used.

Cleanup stopped only owned mocks, named tmux servers, exact hn processes and
their descendants. Final inspection found **no owned process and no listener on
19510–19519**. No commit, push, merge, release or installation was performed.

This is a bounded regression review, not a claim that every fzf option or all
older exploratory cases were recertified. Session discovery uses the repository
mock with index-like letter/digit tokenization and artificial reply delays; the
real index, remote latency, exhaustive query fuzz, and the older full theme/key
matrices were not rerun. Those limits are the reason for a 9.5 score rather than
a claim of perfect parity.
