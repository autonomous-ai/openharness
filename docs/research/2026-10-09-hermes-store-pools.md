# Fresh, complete Hermes store evidence

Hermes repair used a 30-second profile cache and converted both failed reads and multiple rows in one database into no match. A newly created or unreadable competing profile could therefore make an ambiguous conversation appear unique. Hook admission read a fresh listing but accepted the first default or profile result before proving the remaining stores readable. These violate the daemon separation requirement that unavailable identity evidence preserve the current conversation and pending intent.

The former-code golden was recorded in `bc6540795` before production changes. It covers 16 observations through native source declarations, home listing and live repair, with Linux, UTC, fixed time, private homes and built-in SQLite. Host process probes and optional engine loading are forbidden. Re-recording after integrating main `902ab6038` passed without changing the artifact. Proven empty and ambiguous repair pools retain the former result; unsafe incomplete evidence has separate regression assertions.

## Control evidence

`engines/kit/storePool.ts` streams at most 64 profile entries and includes default, populated, unwritten and known custom homes. It captures directory and native database/WAL/rollback-journal metadata, verifies read-only bounded queries, and rechecks all positive and negative claims before returning. Directory aliases count once; every alias path remains part of the proof. File symlinks and multiple hard links hold because their real journals may live beside another name. A changed, unreadable, nonregular or oversized pool raises the eager typed identity hold. Metadata is checked without a later native await; a single returned record's store is checked last. Lookup never initializes a home or database.

Each poll has a shared two-second work budget. SQLite gets the remaining CLI deadline and at most 250 ms of synchronous busy wait. Cached native handles now honor each caller's requested busy timeout. Native input is capped at 64 MiB across all database/WAL/journal files. Schema checks require an ordinary table and stored control columns; hook point lookups require the id to lead the primary index. Repair reads at most 8,193 rows, holds above 8,192 across the complete pool, and filters without an unbounded SQL scan/sort. Original text type, byte length and NUL absence are checked before returning bounded fields. Filesystem calls and synchronous SQLite execution are not cancellable; this is bounded work and change detection, not a hard wall-clock or atomic multi-file snapshot guarantee. Oversized stores stay held with the specific limit reason. Contention or a changed pool retries from fresh evidence.

Repair queries every store and retains all matching interactive rows, including multiple rows inside one store. Proven delegated rows cannot bind; malformed source evidence holds. Only a complete unique result can bind, and a known process home constrains that result. Hook admission verifies the complete pool before accepting or rejecting its source; missing rows, a record from the wrong known home, and conflicting homes remain pending with their reason. Stop capture passes and preserves the proven home. Existing core admission ordering, process fences, Stop tombstones and retry ownership remain in force. Optional history listing caches are outside this control path; the separate optional reader's registry promotion still needs its own authority audit in the completion checklist.

## Validation plan

Run typecheck, architecture, core/services and harnessd per-file coverage, affected native/SQLite/hook/repair tests and unchanged identity goldens. Run serial resume coverage alone. The private bundled Hermes lane runs with its optional module absent and stalled, checking readiness, unreadable later profiles, conflicting records, child rejection and automatic recovery. Mutation checks first require a green baseline and then assertion failures for disconnected declarations/callers, incomplete evidence, ambiguity, deadlines and stale results. Compare CPU, latency and RSS on identical private stores against main. Independent exact-head review and automatic CI precede the authorized merge. No release.

Implementation began after the baseline was verified at 15:12 UTC on October 9. The first focused pass completed at 15:18 UTC: 149 tests, typecheck, architecture and unchanged goldens passed. Later validation, matched cost, review, waiting and merge are recorded with the PR. This item does not complete the entire native-identity group or the overall daemon checklist.

Independent review of `0f0cbbdd6` identified five blockers: file-level aliases could hide a live WAL; output limits did not bound synchronous query work; SQLite text `substr` could normalize NUL-containing source/id values; known custom homes were omitted; repair did not distinguish delegated sources. Each has a real private database or caller regression. The follow-up focus passed 330 tests and unchanged goldens; its initial typecheck correctly failed on the Stop capture result union and was corrected. The first mutation run stopped on a quoting error in a mutant rather than an assertion failure; that run is not passing mutation evidence.

The second review confirmed those corrections and found that Stop still discarded the captured profile twice: while merging its snapshot and when final forget saved the old unbound row. Stop now carries the profile into checkpoint/save and fences changing home authority. The stopped store preserves captured history only for the same registration/process and compatible homes, including the real final-forget path. Composed tests use the actual capture, Stop service, stopped store and forget implementation against private SQLite; process termination and terminal operations are stubs. The first serial pass completed 371 assertions and typecheck, but correctly failed coverage at 99.78% branches because the new nullable transcript normalization lacked an explicit unwritten-resume case. That case was added before rerunning the gate. The shared SQLite handle cache's lifetime under repeated profile churn remains part of the later native-reader resource audit.


## Matched runtime cost

The [raw comparison](2026-10-09-hermes-pool-cost.json) records three interleaved fresh processes per source and workload, ten lookups each, on Node 22.23.2, macOS x64. Former main is `167001ed24abe415f8f411803a6b45d1161dbe1c`; the implementation is `09fb5818936e9caa9968d7c86630d9637259970d`. All stores and homes are private. The embedded driver reproduces the fixtures, including the 4,096 unrelated-row case. Fixture setup and imports are excluded from lookup latency and CPU; peak RSS includes them. Measurements ran without concurrent validation from 15:56:57 to 15:57:11 UTC. These are reference measurements, not a numerical performance gate or Linux measurements.

Fresh positive and negative metadata proof and schema validation cost more than cached incomplete discovery. Bounded prefix reads also cost more than the former filtering query for a large store. Healthy results stayed exact in all 30 lookups per workload; both unavailable workloads returned held in all 30 current lookups, where former code returned an unsafe exact result. The largest observed current lookup was 43.04 ms. The measurements do not establish long-term handle-cache behavior or a hard elapsed-time bound; those limitations remain explicit above.
