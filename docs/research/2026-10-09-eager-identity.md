# Eager identity and transcript location

The owner requires session control to survive missing optional engine modules. The former main implementation still loads engine modules to locate Cursor, Grok, Agy and Copilot transcripts, follow Copilot's in-process resume, discover a Hermes profile, and poll a pending Cursor transcript. These filesystem and process facts belong to the eager core; interpretation remains optional.

Before changing implementation, `otherIdentity.golden.spec.ts` was recorded from main `3a68988a7848adaa6ea329a597cb4cfa82b17fb6`. It retains the existing identity outcomes and adds the Grok hashed-directory fallback, competing Copilot locks and core Cursor discovery of existing and later transcripts. The fixture also carries the previously recorded Hermes ID cases. Linux platform, boot identity, time, UTC, disposable homes and controlled descriptor evidence are pinned. Host Node paths are placeholders. Recording passed all nine cases; the fixture is committed separately before the move.

A lookup must remain available when an optional engine module is absent. A delayed lookup must also respect removal and stop; moving code is not sufficient evidence of that authority boundary. Engine declarations now feed eager kit mechanics. Binding uses the same layouts and PID lock evidence without asking an optional reader. Hermes profile probing and SQLite access are eager too. This keeps the recorded identity outcomes unchanged.

The move exposed lifecycle requirements beyond a mechanical extraction. Binding publishes its name, resume record and client announcement before optional interpretation. Reads retain copied process/binding authority and recheck a resume target's tombstone and newest owner before registration. Cursor location starts outside the optional reader queue; removal, stop and replacement revoke pending lookups. Its discovered path is published immediately.

Attachments serialize by immutable binding identity as well as session id, so a discovered path does not join an obsolete pathless attach. Only the wait for loading code has a five-second bound. Missing or stalled code holds interpretation, logs the reason and makes no normalizer, tail or runtime-profile writes; the binding remains available. A shared import that eventually resolves schedules one current retry per session. Forget removes retry ownership. A newer attach also revokes an earlier hold; any retry already queued checks that ownership again before starting, preventing a recovery from folding the same Cursor first turn twice. Reads that already began interpreting history are never abandoned by this deadline.

Independent review required regression tests for delayed binding publication, stale completion, an exhausted attachment pool, forgotten locator work, a competing resume owner, and a file discovered during the first probe or module load. Tests cover the real attachment tracker and locator together, plus late loader recovery and cleanup. The private-daemon lane removes or stalls optional Cursor/Copilot chunks and exercises PID-based binding, in-process resume and pending transcript discovery. Mutation checks deliberately disconnect both declaration wiring and lifetime checks; only assertion failures count.

The large Cursor-tree test retains its existing two-second discovery assertion. Fixture construction and cleanup each have a thirty-second test bound after concurrent builds exhausted Vitest's default fixture deadline; the isolated original case passed. Routine receipts retain the failed runs as well as the corrected validation.

This is one follow-up, not the end of the audit. Muse/Pi repair, bounded native identity reads, eager OpenCode launch, turn-closing/Stop facts, Cursor task cleanup and submission declarations remain separate work.
