# Eager session control follow-up

The major daemon separation steps and pane-name collision fix have landed. The remaining audit follows the owner's stricter rule: binding, discovery, resume, launch, hook admission and turn closing must not depend on a worker or lazy module. The older other-engine extraction plan allowed lazy helpers in several of these paths; that is no longer the intended boundary. Optional interpretation remains separate.

Before moving identity helpers, the identity and admission goldens were re-recorded from main `d4a0fdea4`. Existing outcomes are unchanged. Added cases cover Hermes history-versus-hook ID rules and an unreadable candidate SQLite store. Platform and environment are pinned, native homes are disposable, and hooks use a private credential on port zero.

The new unreadable-store case exposed a pre-existing bug: `storeSessionSource` maps a failed SQLite read to an empty source, which the Hermes contract treats as interactive. Admission can therefore bind an unverified session and assign the unreadable home. Placing that store before a healthy profile also bypasses the healthy profile's delegated-session rejection. This needs an explicit behavior correction before the mechanical identity move. Its former behavior is recorded separately; the intended correction must retain the current binding and say why admission is pending.

The admission correction distinguishes a verified string source, an absent row, and unavailable or malformed evidence. An explicit empty string retains its declared interactive meaning; NULL, numeric, BLOB and missing source values cannot authorize a binding. A missing or unreadable source leaves the existing binding and home untouched, records the hold reason in the daemon log, and retries automatically. It no longer treats six missed reads as permission to bind. Admission enumerates profiles afresh; incomplete enumeration, failed profile stats and truncated listings hold profile admission. Optional readers retain their existing listing cache. A verified default-home source does not depend on profile enumeration. A verified delegated source is rejected even if an earlier home was unreadable; an interactive profile after unavailable evidence stays held because the home order is unresolved. No native database is written by admission.

The core owns one in-flight lookup and at most 64 unresolved candidates per agent, deduplicated by session ID. Newest candidates are checked first. A rejected child leaves its parent's intent pending; only verified interactive acceptance supersedes older candidates. Capacity backpressure preserves existing candidates and answers the extra delivery with HTTP 429 and an explicit reason, without claiming it was queued. Process or binding changes, Stop's agent tombstone and server shutdown invalidate a lookup before publication. Synchronous and asynchronous notification failures are contained without waiting for optional attachment or retrying a committed binding. HTTP acknowledgement and daemon readiness do not wait for the source lookup. The two golden outcomes for missing and unreadable source evidence change deliberately for this safety fix; all other recorded admission outcomes stay unchanged. `mutate-admission-hold.py` must catch unsafe unavailable-store and absent-row admission, malformed sources, incomplete profiles, a lost held parent, a lost Stop fence, and late publication through assertion failures.

The installed hook treats live backpressure as a hold, makes at most three retries within its existing time budget, and never runs the offline registry writer after that hold, even if a retry disconnects. Before process resolution finishes, Hermes receives HTTP 202 with `pending: false` and an explicit retry response; that early reply cannot falsely promise queue capacity. An exhausted delivery reports the hold to stderr while keeping the vendor hook's no-op JSON output.

Native fired-at timestamps are captured before process resolution and retained across retries. The core keeps a verified-acceptance watermark for each exact process incarnation, seeded from a current persisted binding when needed. Older deliveries cannot replace a newer accepted conversation after resolution, a retry, an emptied queue or a core restart. Rejected children never advance that watermark. Equal-time conflicting candidates and headerless late conflicts stay held until order can be established; arrival order only orders legacy requests this core already observed. Repeated deliveries keep their original position. Additional mutations must catch a lost ordering watermark and live backpressure falling through to the offline writer.

Retry selection visits all incomparable candidates: a child that already returned hold still gets rechecked and rejected after recovery, allowing its equal-time parent to proceed. Known timestamps keep a total order even beside headerless hooks; unknown candidates cannot promote a known older intent. An older duplicate cannot downgrade newer queued evidence, and an equal-stamp retry refreshes stale binding/route authority without promotion. Watermarks for removed or replaced processes are pruned during subsequent admission work, while live-process authority is retained. Four further mutations exercise these ordering and recovery guarantees.

The identity fixture now supplies controlled Linux descriptor entries for Agy's held-lock case. Its recorded result is unchanged and it no longer depends on the host's process table or `lsof`.

The planned identity move keeps filesystem and process mechanics eager and bounded, driven by the existing engine layouts. It removes lazy dependencies from the four transcript finders, Copilot's in-process resume lock, Muse repair, Agy lock lookup, Pi resume/close lookup and Hermes home discovery. Launch helpers, declared Stop rules and submission policies follow separately, each with former-code goldens and mutation checks. Line counts are reference only.
