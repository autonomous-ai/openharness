1. First launch: a tour while Harness sets up

Seven slides, about 6 s each, in order of importance; the arrow or dots move them by hand. Setup now includes the agents: Harness's own Node and CLI (about 30 MB), and, for someone with no agents, OpenCode, Codex and Claude Code (about 290 MB). That took about 30–40 s on the VM's connection and would be nearer 2 minutes on 25 Mbit/s; on a slow connection the slides keep cycling. The bottom line is the only sign of the install: one sentence, a thin bar and the real time left. ▸ opens the log; a failure turns that line red, with Retry. Harness opens by itself, at the end of the slide on screen, once everything is downloaded: no button, nothing to click, and no install screen anywhere afterwards. Changed 2026-10-11: on a computer that is not signed in, the sign-in page (1b) comes at that moment, before Harness opens.

The page. Left: what an account adds. Right: Continue with Google and Continue with Apple. Under the card, one quiet row: Skip starts at the buttons' left edge and Continue with email ends at their right edge. No other words. Return presses Continue with Google. After a click the page stays exactly as it is: the browser opens, and when the account arrives Harness opens, signed in.

Who sees it: only a computer that has never had Harness, and only when nobody is signed in on it. A computer already signed in (from the terminal, say) skips it and Harness opens by itself as before. People who already use Harness never see it.
When: at the end of the slide on screen once setup is done. On Linux, where setup has its own screen and no tour, it shows right after setup.
No time lost: the first workspace (sections 2 and 3) is built behind this page, as it is behind the tour. The agents are already open when the page goes away.
Sign in: Google or Apple, in the browser, as today. When the account arrives, Harness opens on the same first workspace, signed in.
Continue with email: opens the browser on the Autonomous sign-in page, which takes an email and the code sent to it. Kept small on purpose: waiting for a code is slower, and most people will use Google or Apple. New to the desktop app; the sign-in page and the phone app already work this way.
While the browser is open: nothing on the page changes. No "Waiting…" on the button, no Open browser, Copy link or Cancel. Every control stays live: press a button again to open the browser again, pick another way in to switch, or Skip.
Left off this page, to keep it to two buttons: Scan with your phone, the "End-to-end encrypted" line, and the waiting state today's sign-in shows. All stay on the sign-in that Sign in (top right) opens.
Skip: Harness opens without an account, as it does today. The page is not shown again; Sign in stays in the top right (section 5).
What it costs: someone who skips makes one click before their first result, where there was none (−5 on the activation score in 2026-10-08-activation-sim.md, for a prompt before the first result). And if nobody is at the keyboard when setup ends, Harness waits on this page instead of opening.
Not changed: the seven slides, the first workspace itself, and Help ▸ Welcome Tour, which shows the slides only.

The first screen after the tour and the sign-in page (here: skipped, so Sign in is top right). All three are each agent's own screen: OpenCode's start screen with a first task typed in, Codex's and Claude Code's sign-in. Signing in is optional; × closes either pane.

Logic: Downloads happen during the setup tour, not here: OpenCode from the first second (its installer needs only curl), and Codex and Claude Code with one npm command as soon as setup's own Node is in place (both are npm packages, installed into ~/.local exactly as the panes would). The Details line in the tour lists them. When Harness opens (as soon as Harness itself is ready), it creates three ordinary harnesses in one new project. OpenCode opens on its own default screen, focused, with a first task typed into its own message box but not sent: Return sends it; to write something else, the person clears the line first (that is OpenCode's box, so Harness cannot pre-select the text). Codex and Claude Code get no message, so they open on their own sign-in. Nothing in these three panes is drawn by Harness. On a slow network the tour simply lasts longer: Harness opens only when all three agents are in place, so no pane ever shows an install. If a sign-in can't be reached (for example Anthropic blocked on the network), the pane keeps the agent's own error as a shell instead of disappearing. Fixed today on #1052, found by this flow on a VM. Only for someone with none of the three agents; anyone with Claude Code or Codex gets section 3, and OpenCode is not downloaded for them.
