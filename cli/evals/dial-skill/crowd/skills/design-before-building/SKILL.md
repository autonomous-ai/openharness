---
name: design-before-building
description: "You MUST use this before any creative work: creating features, building components, adding functionality or changing behavior. Explores the intent, the requirements and two or three possible designs before a line of implementation is written, and records the chosen design in the repo."
---

Read the code the change touches, write down what it must do and what it must not, sketch two or three approaches with their costs, and pick the simplest one that meets the requirements. Record the choice in a short design note beside the code. Only then start implementing, and come back to the note when the code disagrees with it.
