Project & map origin

Coordinates are WGS 84. Changing the origin relocates all local geometry; vertices remain in east/north meters. A recorded log must be removed before relocation.

Open a project

Open an editable .vector.json file. The existing source changes only when you save to the workspace.

Bring your site

Import WGS 84 polygon GeoJSON. Interior rings become exclusions; a boundary/exclusion kind property is retained. You can edit every vertex after import.

Replace starts a new site draft and removes any recorded log. Undo restores the prior project.

Read a recorded flight

Heading is degrees clockwise from north. Capture events must be 1/0, true/false or yes/no; blank means unknown. Battery is a percentage. No photograph is inferred from a track sample.

Take the field kit with you

Files support planning, review and GIS workflows. They are not an aircraft mission. No vehicle connection or upload is included.

What the model measures

Vector computes local geometry within 5 km of a WGS 84 origin. Boundary insets and exclusion buffers constrain connected horizontal routes. Camera geometry determines ideal footprints and regular-run overlap.

Height is above takeoff. The ground is assumed level with takeoff and the camera points straight down, aligned with each run. No terrain model, obstacle data, airspace check, wind, navigation error or aircraft dynamics are included.

Time includes distance at the configured speed, climb and descent rates, a fixed allowance per capture run and a connected return to takeoff. The usable duration and reserve are inputs, not a validated battery prediction.

Recorded evidence uses only supplied samples. Gaps remain gaps. Footprints require actual event flags, height and heading; they still do not prove that an image exists or is suitable for mapping.
