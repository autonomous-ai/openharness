## Reproduced problems and fixes

| Trigger | Before | After |
| --- | --- | --- |
| Edit an object while Save awaits its response | The response replaces the newer edit, clears its draft and marks the world saved. | Save commits its captured snapshot; later edits and undo/redo remain dirty and recoverable against the saved revision. |
| Load an agent revision, then Undo | Old history can restore the entire earlier world and remove the agent's change. | Accepting an external source clears obsolete undo/redo history. Normal undo after a local save remains available. |
| Source changes project ID, then edit and reload | Draft storage still uses the initial ID, so recovery looks under the wrong key. | Draft identity follows the workspace source. Unsaved imported worlds retain the old source identity until saved; conflicting ID changes retain the draft without accepting the conflicting revision. |
| Check small voxel stairs | The checker requires support directly under the visitor's centre, leaving false gaps before risers. | It considers support across the same 0.52 m footprint used by the movement solver. Step-height, clearance and descent limits remain. |

The save, poll, history, import and recovery handlers were also executed in a Node VM with
deferred responses and in-memory storage. Baseline handlers reproduced all three state-loss
problems. Patched handlers retained edits through delayed saves, network/HTTP errors and
409 conflicts, prevented overlapping saves, cleared obsolete history and recovered migrated
drafts. These are component checks, not browser interactions.
